### Human: Let’s keep it pattern-based. I never fully understood Big-O though. Can you explain it in simple terms?

### Assistant: Big-O is a way to describe **how your algorithm’s running time or memory usage grows as the input size (n) grows**, focusing on the dominant behavior and ignoring constant factors.

A simple way to think about it:

- **O(1) — Constant time**  
  The work doesn’t really grow with input size.  
  Example: Accessing `arr[5]` in an array.

- **O(n) — Linear time**  
  Work roughly doubles if input doubles.  
  Example: A single loop through a list of `n` items.

- **O(n²) — Quadratic time**  
  Work grows like `n * n`. Doubling input ~ quadruples work.  
  Example: A nested loop that compares every pair of elements.

- **O(log n) — Logarithmic time**  
  Work grows slowly as input grows; doubling input adds a constant amount of extra work.  
  Example: Binary search in a sorted array.

- **O(n log n)**  
  Common for efficient sorting algorithms like mergesort or heapsort.

To analyze a piece of code, you:
1. Count roughly how many times the main operations run in terms of `n`.
2. Keep the dominant term and drop constants and lower-order terms.

Example:

```python
def example(arr):  # arr has length n
    total = 0              # O(1)
    for x in arr:          # runs n times
        total += x         # O(1) each time
    return total           # O(1)
```

Total work: about `1 + n * 1 + 1` → **O(n)**.

Another example:

```python
def pairs(arr):            # arr has length n
    for i in range(len(arr)):        # n
        for j in range(len(arr)):    # n
            print(arr[i], arr[j])    # constant
```

Total work: about `n * n` → **O(n²)**.

To check your understanding, want to try classifying the complexity of this function?

```python
def mystery(n):
    i = 1
    while i < n:
        i *= 2
```

What Big-O time complexity do you think `mystery` has with respect to `n`?

### Human: I think that’s O(log n) because i doubles each time until it reaches n. Is that right?

### Assistant: Yes, that’s exactly right.

Reasoning:
- `i` starts at 1 and doubles each time: 1, 2, 4, 8, …, up to about `n`.
- After `k` iterations, `i = 2^k`. The loop stops when `2^k >= n`.
- That means `k ≈ log₂(n)` iterations → **O(log n)** time.

This “keep dividing or multiplying by a constant factor each step” pattern is typical for logarithmic complexity, just like binary search.
