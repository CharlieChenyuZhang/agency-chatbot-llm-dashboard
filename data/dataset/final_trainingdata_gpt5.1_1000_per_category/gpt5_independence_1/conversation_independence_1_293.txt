2. Database (Postgres via Supabase + Prisma):

Prisma schema sketch (`schema.prisma`):

- DataPulse:

```prisma
model DataPulseRaw {
  id        Int      @id @default(autoincrement())
  sourceId  String
  ts        DateTime
  value     Float
  createdAt DateTime @default(now())
}

model DataPulseDailyAggregate {
  id        Int      @id @default(autoincrement())
  date      DateTime
  metric    String
  value     Float
  createdAt DateTime @default(now())
}
```

- ExpTrack:

```prisma
model Experiment {
  id          Int       @id @default(autoincrement())
  name        String
  hypothesis  String
  primaryMetric String
  status      String   // planned, running, completed, cancelled
  startDate   DateTime?
  endDate     DateTime?
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  metrics     ExperimentMetric[]
}

model ExperimentMetric {
  id            Int       @id @default(autoincrement())
  experimentId  Int
  variant       String    // control, treatmentA, etc.
  ts            DateTime
  users         Int
  conversions   Int

  experiment    Experiment @relation(fields: [experimentId], references: [id])

  @@index([experimentId])
}
```

- ModelWatch:

```prisma
model ModelMetric {
  id          Int      @id @default(autoincrement())
  modelName   String
  segment     String   // e.g. "US", "EU", "All"
  ts          DateTime
  accuracy    Float
  precision   Float
  recall      Float
  createdAt   DateTime @default(now())

  @@index([modelName, segment, ts])
}

model ModelAlert {
  id          Int      @id @default(autoincrement())
  modelName   String
  segment     String
  createdAt   DateTime @default(now())
  severity    String   // info, warning, critical
  message     String
}
```

3. API routes (high level behavior):

- `/api/datapulse/metrics`:

- `/api/exptrack/experiments`:

- `/api/exptrack/metrics`:
  - GET: metrics for a given experiment (id) and date range.

- `/api/modelwatch/metrics`:
  - GET: time-series metrics by `modelName`, `segment`, date range.

- `/api/modelwatch/alerts`:
  - GET: list alerts (optionally filter by model or severity).
