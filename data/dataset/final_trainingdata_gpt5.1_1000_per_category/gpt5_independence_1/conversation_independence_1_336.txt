## Business Rules for Habit Streak

For any task where `isHabit = true`:

1. **When user hits “Complete Today”**:
   - If `lastCompletedDate` is `null`:
     - Set `streak = 1`
     - Set `lastCompletedDate = today`
   - Else:
     - Compute the difference in whole days between `today` and `lastCompletedDate`:
       - If `diffDays = 0`:  
         - Do nothing to `streak` (already completed today).
       - If `diffDays = 1`:  
         - Increment `streak` by 1  
         - Update `lastCompletedDate = today`
       - If `diffDays > 1`:  
         - Reset `streak = 1`  
         - Set `lastCompletedDate = today`

2. **For non-habit tasks (`isHabit = false`)**:
   - `POST /tasks/:id/complete` should:
     - Just set `status = DONE`
     - Leave `streak` and `lastCompletedDate` unchanged.

I’ll assume you store timestamps in UTC and treat “today” as the UTC date for simplicity.

---

## Example Express Route with Prisma

```ts
import { Request, Response } from 'express';
import { prisma } from '../prismaClient'; // your prisma instance
import { differenceInCalendarDays } from 'date-fns';

export const completeTask = async (req: Request, res: Response) => {
  const { id } = req.params;

  try {
    const task = await prisma.task.findUnique({ where: { id } });

    if (!task) {
      return res.status(404).json({ message: 'Task not found' });
    }

    const now = new Date();

    // Non-habit: just mark as DONE
    if (!task.isHabit) {
      const updated = await prisma.task.update({
        where: { id },
        data: {
          status: 'DONE',
          updatedAt: now,
        },
      });

      return res.json(updated);
    }

    // Habit logic
    let newStreak = task.streak;
    let newLastCompletedDate = task.lastCompletedDate;

    if (!task.lastCompletedDate) {
      // First completion ever
      newStreak = 1;
      newLastCompletedDate = now;
    } else {
      const diffDays = differenceInCalendarDays(
        now,
        task.lastCompletedDate
      );

      if (diffDays === 0) {
        // Already completed today; keep streak as is
        newStreak = task.streak;
        newLastCompletedDate = task.lastCompletedDate;
      } else if (diffDays === 1) {
        // Consecutive day
        newStreak = task.streak + 1;
        newLastCompletedDate = now;
      } else if (diffDays > 1) {
        // Missed at least one day
        newStreak = 1;
        newLastCompletedDate = now;
      }
    }

    const updated = await prisma.task.update({
      where: { id },
      data: {
        status: 'DONE',
        streak: newStreak,
        lastCompletedDate: newLastCompletedDate,
        updatedAt: now,
      },
    });

    return res.json(updated);
  } catch (err) {
    console.error(err);
    return res.status(500).json({ message: 'Internal server error' });
  }
};
```

**Notes:**
- This uses `date-fns` for `differenceInCalendarDays`. Add it with:
  - `npm install date-fns`
- It ensures:
  - You don’t double-increment on the same day.
  - You correctly reset the streak when days are missed.

## WebSocket Events

Define your Socket.IO events like this:

- Client -> Server:
  - `note:join` – `{ noteId, userId }`
  - `note:leave` – `{ noteId, userId }`
  - `note:update` – `{ noteId, content }`
  - `user:presence` – `{ noteId, userId, name, color }`

- Server -> Clients (in same room):
  - `note:content` – `{ noteId, content }`
  - `note:presence` – `{ users: { userId, name, color }[] }`

## Implementation Plan

**Step 1 – Backend Scaffold**
1. Create `collabnotes-api` (or just `collabnotes` if monorepo).
2. Set up Express + Socket.IO server.
3. Add PostgreSQL + Prisma with `Note` model.
4. REST endpoints:
   - `GET /notes` – list notes
   - `POST /notes` – create note
   - `GET /notes/:id` – get single note (for initial load)

**Step 2 – Real-Time Logic**
1. When client connects and emits `note:join`:
   - Add user to Socket.IO room `note:<id>`.
   - Emit `note:content` with current note content to the joining client.
   - Update presence for all clients in the room.

2. When client emits `note:update`:
   - Broadcast updated content to other clients in the room.
   - Debounce/schedule DB save of `content`.

3. When client disconnects or emits `note:leave`:
   - Remove from room and update presence.

**Step 3 – Frontend**
1. Create `collabnotes-web` with React + TS + Tailwind.
2. Pages:
   - `/` – Notes list + “New Note” button.
   - `/notes/:id` – Editor page with:
     - Title input
     - Textarea or editor for content
     - Presence avatars with names/colors

3. On `/notes/:id`:
   - Fetch initial note data from REST API.
   - Connect to WebSocket with `noteId` and `user` info.
   - Listen to:
     - `note:content` -> update editor content.
     - `note:presence` -> update presence list.

4. Handle local editing:
   - On local change, update state and emit `note:update` with new content.
   - Optionally, throttle emits (e.g., every 100–200ms).
