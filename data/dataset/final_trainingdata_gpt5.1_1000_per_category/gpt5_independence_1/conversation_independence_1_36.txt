Step 1 (Today, Part A) – Intuition for Big-O:
- Concept: Measure how runtime grows as input size n grows.
- Common complexities:
  - O(1): constant
  - O(log n): logarithmic
  - O(n): linear
  - O(n log n): “linearithmic”
  - O(n²): quadratic

Simple rules:
- Drop constants: O(3n) → O(n)
- Keep the dominant term: O(n² + n) → O(n²)

### Human: I always get confused about Big-O. Can you explain it simply before we check my answers?

### Assistant:
Think of Big-O as “how fast the work grows” when inputs get huge.

Analogy:
- Imagine processing emails.
- If it takes you 1 second per email, then 100 emails ≈ 100 seconds, 10,000 emails ≈ 10,000 seconds. Double emails → double time. That’s O(n).
- If you have to compare every email to every other email (like checking all pairs), 100 emails → about 10,000 checks, 10,000 emails → about 100 million checks. Time grows like n². That’s O(n²).

Core ideas:

1) We ignore constants and small details.
- O(2n) and O(100n) are both O(n) because when n is huge, the factor 2 or 100 doesn’t matter compared to n itself.

2) We care about worst-case growth.
- Big-O usually describes “upper bound” behavior: how bad can it get as n grows.

3) Examples:
- One loop over a list of size n:
  - Does n operations → O(n)
- Two nested loops over n:
  - n * n = n² operations → O(n²)
- Repeatedly doubling i: 1, 2, 4, 8, … until n:
  - You double about log₂(n) times → O(log n)

Next step: Linked lists (singly linked)

Concept:
- Instead of a contiguous array, a linked list is a chain of nodes, each holding:
  - `value`
  - `next` pointer to the next node (or None).

Core operations:
- Insert at head: O(1)
- Traverse: O(n)
- Search by value: O(n)
- No O(1) random access like `arr[i]`.

Here’s a basic singly linked list node and a simple list wrapper in Python:

```python
class Node:
    def __init__(self, val):
        self.val = val
        self.next = None

class LinkedList:
    def __init__(self):
        self.head = None

    def insert_at_head(self, val):
        new_node = Node(val)
        new_node.next = self.head
        self.head = new_node

    def to_list(self):
        result = []
        curr = self.head
        while curr:
            result.append(curr.val)
            curr = curr.next
        return result
```

### Human: I think I understand. How exactly would I write insert_at_tail and find?

### Assistant:
Build directly on the earlier `LinkedList`:

```python
class LinkedList:
    def __init__(self):
        self.head = None

    def insert_at_head(self, val):
        new_node = Node(val)
        new_node.next = self.head
        self.head = new_node

    def insert_at_tail(self, val):
        new_node = Node(val)
        if self.head is None:
            self.head = new_node
            return
        curr = self.head
        while curr.next is not None:
            curr = curr.next
        curr.next = new_node

    def find(self, target):
        curr = self.head
        while curr is not None:
            if curr.val == target:
                return True
            curr = curr.next
        return False

    def to_list(self):
        result = []
        curr = self.head
        while curr:
            result.append(curr.val)
            curr = curr.next
        return result
```

1) Stacks
- LIFO: Last-In, First-Out.
- Operations:
  - `push(x)`
  - `pop()`
  - `peek()`
- Typical uses:
  - Undo operations
  - Parentheses matching
  - DFS (depth-first search) can be implemented with a stack.

Python implementation with list:

```python
class Stack:
    def __init__(self):
        self.items = []

    def push(self, x):
        self.items.append(x)

    def pop(self):
        return self.items.pop()  # assume non-empty for now

    def peek(self):
        return self.items[-1]

    def is_empty(self):
        return len(self.items) == 0
```

2) Queues
- FIFO: First-In, First-Out.
- Operations:
  - `enqueue(x)`
  - `dequeue()`
- Typical uses:
  - Task scheduling
  - BFS (breadth-first search) on graphs/trees.

Python implementation with `collections.deque`:

```python
from collections import deque

class Queue:
    def __init__(self):
        self.items = deque()

    def enqueue(self, x):
        self.items.append(x)

    def dequeue(self):
        return self.items.popleft()

    def is_empty(self):
        return len(self.items) == 0
```

Core traversals (we’ll implement all recursively):
- Preorder: root, left, right
- Inorder: left, root, right
- Postorder: left, right, root

def preorder(root):

    return [root.val] + preorder(root.left) + preorder(root.right)
