**Coding – why scan from the right?**

Your intuition is good: scanning from the left with a set *does* find a duplicate, but not necessarily the **first index that belongs to a duplicate pair**.

If we scan from the left:

- Maintain a set `seen`.
- When we see a value that’s already in `seen`, we return **the current index**.

Example:
- Array: [3, 1, 4, 1, 5]
  - i=0 (3): not in set → add 3.
  - i=1 (1): not in set → add 1.
  - i=2 (4): not in set → add 4.
  - i=3 (1): already in set → return 3.

But the **first index that is part of a duplicate pair** is 1 (the first 1), not 3 (the second 1).

Scanning from the right fixes this:
- We discover duplicates starting from the end, and each time we find one, we keep updating the answer with a **smaller** index, so we end up with the first such index.
