Summary: **Structuring user interactions**

I think it’s important for me to set some default assumptions, like assuming GitHub as the platform. However, I need to be transparent about my assumptions and offer to adjust based on user preferences. When prompting for information like repo access, date ranges, or whether to include closed issues, I should ask questions to clarify.

The starting message will be: "List issues labeled bug in my most active repo." I’ll confirm what "most active" means, and touch on whether they want only open issues. Balancing decision-making is key, so I’ll sometimes choose defaults without asking.
