**1. Q-network structure (PyTorch)**

Conceptually:

```python
import torch
import torch.nn as nn

class DQN(nn.Module):
    def __init__(self, state_dim, action_dim):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(state_dim, 128),
            nn.ReLU(),
            nn.Linear(128, 128),
            nn.ReLU(),
            nn.Linear(128, action_dim)
        )

    def forward(self, x):
        return self.net(x)  # returns Q-values for each action
```

Key points:
- `state_dim` for CartPole is 4.
- `action_dim` is 2 (left or right).
- You can tweak hidden sizes (64, 128, etc).

**2. Replay buffer structure**

Minimal, but functional:

```python
import random
from collections import deque

class ReplayBuffer:
    def __init__(self, capacity):
        self.buffer = deque(maxlen=capacity)

    def push(self, state, action, reward, next_state, done):
        self.buffer.append((state, action, reward, next_state, done))

    def sample(self, batch_size):
        batch = random.sample(self.buffer, batch_size)
        states, actions, rewards, next_states, dones = zip(*batch)
        return states, actions, rewards, next_states, dones

    def __len__(self):
        return len(self.buffer)
```

In the training loop, you’d:
- Call `buffer.push(s, a, r, s_next, done)` at each step.
- Once `len(buffer) >= batch_size`, you call `sample` and convert the outputs into PyTorch tensors.

**Conceptual training step (inside your main loop)**

Assuming you have:
- `policy_net`, `target_net` (instances of `DQN`)
- `optimizer` = `torch.optim.Adam(policy_net.parameters(), lr=...)`

Rough structure:

```python
# states:  [batch_size, state_dim]
# actions: [batch_size]
# rewards: [batch_size]
# next_states: [batch_size, state_dim]
# dones:  [batch_size]  (0.0 or 1.0)

q_values = policy_net(states)                    # [batch_size, action_dim]
# gather Q(s, a) for each taken action
state_action_values = q_values.gather(1, actions.unsqueeze(1)).squeeze(1)

with torch.no_grad():
    next_q_values = target_net(next_states)     # [batch_size, action_dim]
    max_next_q_values, _ = next_q_values.max(dim=1)
    target_values = rewards + gamma * max_next_q_values * (1 - dones)

loss = torch.nn.functional.mse_loss(state_action_values, target_values)

optimizer.zero_grad()
loss.backward()
optimizer.step()
```

You’d typically:
- Run this training step every environment step (once you have enough samples).
- Copy `policy_net` weights to `target_net` every N steps (e.g., every 1000 steps).

       `reward_t = (P_{t+1} - P_t) * position_t - transaction_costs`

     - `reset()` returns initial state (starting at day N)

       - Moves to next day
       - Computes reward
       - Returns `(next_state, reward, done, info)`

   - You can reuse a DQN-like algorithm, but:
     - Be aware that trading rewards can be sparse and noisy.
   - Alternatively, consider policy gradients or actor-critic (e.g., PPO), but that’s a bit more advanced.

   - **Look-ahead bias**: Accidentally using future prices in your state or reward beyond what would be known at time t.

   - **Short evaluation periods**:

     - Always include some transaction cost.
     - Always evaluate against buy-and-hold.
     - Always use a held-out test period.
