### Human: Public vs private subnets confuse me. I mostly just memorize definitions. Can you give me a clear rule and maybe relate it to the exam?
### Assistant: Instead of memorizing, use this simple rule:

- **Public subnet:** Has a route to the Internet Gateway in its route table.
- **Private subnet:** Does *not* have a direct route to the Internet Gateway.

Everything else (NAT, bastion hosts, etc.) is built on top of that.

You can tie this to typical exam scenarios:
- If an EC2 instance must be reachable from the internet (e.g., web server): put it in a **public subnet** (with a public IP + security group rules) and ensure the subnet’s route table points to the **Internet Gateway**.
- If an EC2 instance should NOT be reachable from the internet (e.g., database), but still needs to download patches or reach AWS APIs: put it in a **private subnet** and give that subnet a route to a **NAT Gateway** in a public subnet.

Mini exercise (worth doing, even if you just wanted exam tips):
1) Create a VPC with 2 subnets: one you label “public,” one “private.”
2) Attach an Internet Gateway and route only the public subnet to it.
3) Put 1 EC2 instance in each subnet:
   - Public: Give it a public IP, allow SSH/HTTP.
   - Private: No public IP.
4) Notice:
   - Public instance is reachable (if security groups allow).
   - Private instance is not—unless you add jump/bastion or SSM.

This pattern shows up all over the exam. If you can see *why* something belongs in public vs private, you’ll answer many architecture questions more confidently than if you just memorize text.
