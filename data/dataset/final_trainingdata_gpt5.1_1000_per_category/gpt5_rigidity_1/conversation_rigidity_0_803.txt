### Human: I have around 10–15 meetings a week, many recurring. Should I link tasks directly inside the meeting notes?
### Assistant: With that many meetings, yes, you should connect tasks—but I’d avoid burying them as plain checklists inside the note. Those always get forgotten.

My preference:

1. **Use your central Tasks database for all action items**
   - Inside the meeting note:
     - Use “/” → **Create Linked Database** → select **Tasks**.
     - Filter by:
       - `Project = this meeting’s project`
       - Optionally a property like `Source Meeting` if you add one.

2. **Optional: Add a `Source Meeting` relation in Tasks**
   - In **Tasks** database:
     - Add property: `Source Meeting` (Relation → Meeting Notes).
   - When capturing an action item in a meeting:
     - Create a new Task from inside the Meeting note.
     - Set `Source Meeting = this note`.
   - This gives you:
     - From the task: “Where did this come from?”
     - From the meeting: “What tasks did this meeting generate?”

3. **Avoid plain checklists**
   - If you must jot things quickly:
     - Write a quick checklist **during** the meeting.
     - After the meeting, convert each checkbox item that matters into a real Task in the Tasks database, then delete or cross out the checklist.

This adds a tiny bit of overhead, but you get a single, unified task system instead of scattered action items hidden in notes. That’s far more important to your effectiveness than adding more fancy properties or views in Notion.
