1) Big-O idea:

   - We ignore constants and lower-order terms, focusing on dominant growth.

2) Example 1 (O(n)):
   - Code:

   - The loop runs once per element, so if n doubles, time roughly doubles → O(n).

3) Example 2 (O(n²)):

     ```python
     def print_pairs(arr):
         for x in arr:
             for y in arr:

     ```

Step-by-step logic (no code):

2) Understand rotation right by k: the last k elements move to the front, and the others shift right.
3) Conceptually split the list into two parts: [first n-k elements] and [last k elements].
4) New order after rotation: [last k elements] followed by [first n-k elements].
5) To do this in-place efficiently, we can use a sequence of reversals rather than extra arrays.
### Human: Now show me the Python code for that rotation using the reversal idea, but keep it under 15 lines and don’t include any comments.
### Assistant: ```python
def rotate_right(nums, k):
    n = len(nums)
    if n == 0:
        return
    k %= n
    def rev(i, j):
        while i < j:
            nums[i], nums[j] = nums[j], nums[i]
            i += 1
            j -= 1
    rev(0, n - 1)
    rev(0, k - 1)
    rev(k, n - 1)
```

### Human: I’ve heard of recursion being related to stacks. In exactly 3 bullet points, explain that connection at a very high level.
### Assistant: - Each function call in a program is placed on a call stack, which remembers where to return and what local variables exist.
- When you use recursion, each recursive call adds a new frame to this call stack, just like pushing onto a stack.
- When a recursive call finishes, its frame is popped from the call stack, returning control to the previous frame.
