First, here’s a reusable, stack-agnostic workflow:

1. **Clarify the problem**
   - What is *actually* wrong? (symptoms)
   - When does it happen? (triggers, frequency, environment)
   - What should happen instead? (expected behavior)
   - Is it reproducible? If so, what’s the *minimal* repro steps?

2. **Gather evidence**
   - Logs (client, server, infrastructure)
   - Metrics (CPU, memory, latency, error rates)
   - Recent changes (code, config, dependencies, infra)
   - Version/environment details (OS, language runtime, feature flags)

3. **Narrow the scope**
   - Can you reproduce it locally?
   - Does it affect all users or some?
   - Does it occur in all environments (dev/stage/prod)?
   - Use “binary search” in the system: disable/enable components, roll back features, or bisect code changes to isolate the culprit.

4. **Form hypotheses**
   - Based on the evidence, list 2–5 plausible root causes.
   - Prioritize them by likelihood and ease of testing.

5. **Test hypotheses systematically**
   - For each hypothesis:
     - Predict what you’d see *if it were true*.
     - Design a small experiment (extra logging, a temporary code change, a feature flag toggle, a local repro).
     - Run it and record what you observed.
   - Discard or refine hypotheses based on real observations.

6. **Confirm the root cause**
   - Find a single change that:
     - Makes the bug appear when applied.
     - Makes it disappear when reverted/fixed.

7. **Implement and verify the fix**
   - Fix the root cause, not just the symptom.
   - Add or update tests.
   - Monitor after deployment to confirm it’s truly gone.

8. **Capture the learning**
   - Update runbooks, alerts, dashboards.
   - Add guardrails (better logging, feature flags, safer defaults).
