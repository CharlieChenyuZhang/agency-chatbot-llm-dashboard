### Human: Now give me the answers and very short explanations (1 sentence each) for these 10 questions in a numbered list.
### Assistant: 1. Use an Auto Scaling group with EC2 instances across multiple AZs behind an Application Load Balancer and enable RDS Multi-AZ; this improves availability without major code changes.
2. S3 Standard-IA or S3 Intelligent-Tiering, because they are optimized for infrequently accessed data that still requires rapid retrieval at lower cost than S3 Standard.
3. Use S3 for static website hosting fronted by CloudFront with a custom domain and appropriate cache settings for low-latency global delivery without managing servers.
4. Attach an IAM role to the EC2 instance with an appropriate S3 access policy, so temporary credentials are securely provided by the instance metadata service.
5. Place a NAT gateway in each public subnet and configure private subnets’ route tables to send 0.0.0.0/0 traffic to the NAT gateway, allowing outbound-only internet access.
6. Amazon DynamoDB, because it is a fully managed NoSQL database that offers flexible schema, automatic scaling, and single-digit millisecond performance at any scale.
7. Use Amazon SQS FIFO queues so messages are processed in order with exactly-once processing semantics for each message group (e.g., per customer).
8. Use a lift-and-shift strategy with EC2 Auto Scaling behind a load balancer for web/app tiers and Amazon RDS for the database, possibly using Database Migration Service for minimal downtime.
9. Use S3 Object Lock in compliance mode with a retention period of 7 years (optionally combined with versioning) to prevent deletion or overwrite during that time.
10. Use a centralized egress VPC design with a shared services VPC hosting the security appliance and VPC peering or AWS Transit Gateway to route outbound traffic through it in a highly available configuration.

### Assistant: 1. Confusing security groups (stateful, instance/subnet level) with NACLs (stateless, subnet level).

7. Ignoring the shared responsibility model, especially for encryption, patching, and network security.

### Human: Briefly explain the difference between VPC peering and AWS Transit Gateway, in 3 bullets or fewer.
### Assistant: - VPC peering connects two VPCs directly in a one-to-one relationship with no transitive routing.
- AWS Transit Gateway acts as a central hub that connects multiple VPCs and on-premises networks with scalable, transitive routing.
- Transit Gateway is better for large, hub-and-spoke topologies, while peering is simpler for a small number of VPC connections.
