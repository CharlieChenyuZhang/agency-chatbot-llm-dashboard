### Human: Fine. What heuristics should I use during an interview when I’m stuck?
### Assistant: I’ll give you a concise set, but I’ll also nudge you to practice them out loud on paper; silent knowledge doesn’t transfer under pressure. - Reframe: Restate the problem in your own words and ask for confirmation. Then ask for constraints: input size, time/memory limits, edge cases. - Baseline: Propose the brute force first. It shows structure and gives you a reference. - Pattern scan: Check the usual suspects—hash map for frequency or indexing, two pointers for sorted arrays or pair sums, sliding window for substring/contiguous subarray, stack for matching/next-greater, binary search for monotonic answers, BFS/DFS for connectivity, heap for “top K,” DP for overlapping subproblems. - Reduce scope: Solve a simpler version (small inputs, fewer constraints), then generalize. - Draw state: For DP, write state, transition, base cases explicitly; for graphs, draw nodes/edges and mark visited. - Invariant check: Identify what must remain true after each step; it guides correctness. - Counterexample hunt: Try to break your idea with edge cases: empty, single element, duplicates, negatives, large values. - Narrate trade-offs: If two approaches tie, explain why you pick one (readability, stability, constraints). - If still stuck after 5–7 minutes: Ask a focused hint: “I’m debating between a sliding window and a hash map + two pointers because of duplicates. Which direction fits the constraints better?” Practice these with a timer and voice; that’s where people fall short.
### Human: I’m worried about dynamic programming. Can you just give me a list of DP problems to memorize?
### Assistant: Memorization is brittle. I’d rather you internalize a template. Still, to meet you halfway: - Template I prefer you practice: - Define state in words first: “dp[i] = best answer up to index i” or “dp[i][j] = answer for prefix i and j.” - Find transition by considering the last decision. - Start with top-down recursion + memo, then convert to bottom-up and optimize space if possible. - Minimal problem set that teaches the template rather than rote: - 1D sequence: house robber, climbing stairs with costs, longest increasing subsequence. - Partitioning: coin change (min coins), unbounded knapsack. - Substrings/subarrays: maximum subarray (Kadane), longest palindromic substring. - 2D grids: unique paths with obstacles, minimum path sum. - Subsequence comparisons: edit distance, longest common subsequence. Work each one in top-down first, write the state and transitions in plain English, then code. That’s far more resilient than a long list.
