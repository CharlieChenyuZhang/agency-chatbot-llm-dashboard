Title: Dockerize a FastAPI App in 10 Minutes (with Local Debugging) Who this is for - You know a bit of Python and want a minimal, reproducible FastAPI setup in Docker. What you’ll build - A tiny FastAPI app, a production-ready Dockerfile, and a docker-compose file for local hot-reload. Prerequisites - Python 3.11+ installed locally - Docker Desktop or Docker Engine running 1) Create the app - mkdir fastapi-docker && cd fastapi-docker - python -m venv .venv - source .venv/bin/activate (macOS/Linux) or .venv\Scripts\activate (Windows) - pip install fastapi uvicorn[standard] - Create app/main.py with: from fastapi import FastAPI app = FastAPI() @app.get("/") def read_root(): return {"status": "ok"} - Test locally: uvicorn app.main:app --reload --port 8000 - Visit http://localhost:8000 and http://localhost:8000/docs 2) Add a production Dockerfile - Create Dockerfile: FROM python:3.11-slim WORKDIR /app ENV PYTHONDONTWRITEBYTECODE=1 ENV PYTHONUNBUFFERED=1 RUN pip install --no-cache-dir fastapi uvicorn[standard] COPY app app EXPOSE 8000 CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"] - Build: docker build -t fastapi-docker:prod . - Run: docker run -p 8000:8000 fastapi-docker:prod - Check http://localhost:8000 3) Local development with hot-reload (docker-compose) - Create requirements.txt: fastapi uvicorn[standard] - Update Dockerfile.dev: FROM python:3.11-slim WORKDIR /app COPY requirements.txt . RUN pip install --no-cache-dir -r requirements.txt COPY app app EXPOSE 8000 CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000", "--reload"] - Create docker-compose.yml: services: api: build: context: . dockerfile: Dockerfile.dev volumes: - ./app:/app/app ports: - "8000:8000" environment: - PYTHONUNBUFFERED=1 - Start: docker compose up --build - Edit app/main.py; changes should hot-reload. 4) Health checks and simple logging - Add a /health endpoint: @app.get("/health") def health(): return {"ok": True} - Test: curl http://localhost:8000/health 5) Common pitfalls - Port already in use: Change host port mapping (e.g., 8001:8000). - File permission issues on Windows with volumes: Consider WSL2 and ensure your code folder is in the Linux filesystem. - Dependencies not updating in container: Rebuild when requirements.txt changes or use pip-tools. 6) Next steps - Add a production server like gunicorn with uvicorn workers. - Use a multi-stage Dockerfile to shrink image size. - Add a CI workflow to build and push your image to a registry. - Put Nginx or Caddy in front for TLS.
