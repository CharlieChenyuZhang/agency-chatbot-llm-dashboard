### Human: Fine. How do I export from iCloud Keychain?
### Assistant: Two practical paths: On a Mac (most straightforward): 1) Make sure iCloud Keychain is enabled: System Settings > Apple ID > iCloud > Passwords and Keychain = On. 2) Open Safari > Settings > Passwords (unlock with Touch ID/password). 3) Click the three dots (…) > Export All Passwords… > Save the CSV to a temporary folder. 4) Bitwarden Web > Tools > Import Data > Format: Safari (CSV) > Choose file > Import. 5) After verifying items imported, delete the CSV and empty Trash. From Windows if you don’t want to use a Mac: 1) Install iCloud for Windows from Microsoft Store; sign in and enable Passwords. 2) Install the “iCloud Passwords” extension in Chrome. 3) Let it sync, then in Chrome Password Manager export to CSV. 4) Import that CSV into Bitwarden (Format: Chrome). 5) Delete the CSV afterwards. Tell me which route you’re taking, and I’ll tailor the next steps.
### Human: I’m worried about the CSV file being unencrypted.
### Assistant: Good instinct. Safer handling: - Do it on a device with full‑disk encryption (Mac with FileVault, Windows with BitLocker). - Save the CSV to a clearly named temporary folder that’s not synced to cloud (e.g., not Desktop if you sync Desktop/Documents). - Keep the file for as short a time as possible: export, import, verify, delete, empty Trash/Recycle Bin. - If you must transfer the file, zip it with strong encryption and a password you don’t reuse, then delete the zip after import. - Extra cautious Mac option: create an encrypted disk image (Disk Utility > New Image > Blank Image, AES‑encrypted), put the CSV there, import from it, then delete the image. Once imported and verified, delete the CSV and any zips, then empty Trash.
### Human: What about passkeys and 2FA codes?
### Assistant: Passkeys - Existing passkeys are usually stored by the platform (iCloud Keychain on Apple, Google Password Manager on Android/Chrome). There’s no universal export yet. - Bitwarden supports creating and using passkeys, but you can’t automatically import existing ones. - Practical approach: leave existing passkeys where they are. As you revisit accounts, add or recreate passkeys in Bitwarden or keep using platform passkeys. It’s fine to have both. 2FA codes (TOTP) - Option A: Store TOTPs in Bitwarden for convenience (premium feature) so username/password/TOTP all autofill together. - Option B (more secure separation): keep TOTPs in a separate authenticator (Aegis on Android, Raivo/2FAS on iOS). This reduces single‑point‑of‑failure risk. - Migration note: most sites require re-enrolling 2FA. When you log in next, go to the site’s security settings, disable/re-enable 2FA, and scan the new QR code with your chosen authenticator (or Bitwarden). - Strong defense-in-depth: add a FIDO2 security key (e.g., YubiKey) where supported. If you want, I can help you pick a TOTP app or set up Bitwarden Premium for codes.
