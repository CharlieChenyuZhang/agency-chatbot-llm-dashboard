### Human: Give me a memory trick for S3 storage classes differences.
### Assistant: Quick mental hooks: - Standard = “always on”: 11 9s durability, 99.99% availability, multi-AZ. - Standard-IA = “infrequent but important”: multi-AZ, cheaper storage, retrieval fee; min 30 days. - One Zone-IA = “single-zone spare tire”: one AZ only, cheaper than IA; min 30 days; not for critical resilience. - Intelligent-Tiering = “auto-sorter”: moves between frequent/infra tiers automatically; tiny monitoring fee; good when patterns change. - Glacier Instant Retrieval = “archive, but I might need it fast”: milliseconds access; min 90 days. - Glacier Flexible Retrieval = “I can wait minutes-hours”: expedited/standard/bulk; min 90 days. - Glacier Deep Archive = “cold storage”: hours access; min 180 days; cheapest. Mnemonic ladder: - Hot (Standard) → Cool (IA) → Local Cool (One Zone-IA) → Smart (Intelligent) → Archive Fast (Glacier IR) → Archive Normal (Glacier Flexible) → Deep Freeze (Deep Archive). Remember: only S3 and DynamoDB have Gateway Endpoints; lifecycle policies can transition between classes, but retrieval and minimum storage durations affect cost.

### Human: Can you check my weak area: I think NAT Gateway can be shared across AZs to improve HA.
### Assistant: Close, but important correction: a NAT Gateway is AZ‑specific. For high availability: - Deploy a NAT Gateway in each AZ. - Route each private subnet to the NAT Gateway in its own AZ. - If you route to a NAT in another AZ, you introduce cross‑zone dependency and potential single point of failure. Alternative (less recommended for prod): NAT Instances with custom failover scripts. Managed NAT Gateways are the exam‑preferred answer.
