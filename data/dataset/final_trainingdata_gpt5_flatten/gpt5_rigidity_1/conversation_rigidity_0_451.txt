### Human: That loop with glab looks brittle. I’d rather stick to git. Anything else I should watch out for with the MR refs?
### Assistant: A few guardrails (this is why I prefer triaging first): - The remote name: if your GitLab remote isn’t origin, replace origin in the commands - Merge ref vs head ref: you fetched head (the source branch). ### Human: How would I limit to only MRs labeled “Ready”?
### Assistant: My preference is to filter in the web UI first and only pull down what truly needs local work. But if you want it scripted, labels aren’t exposed through the raw refs—so you need the API to filter, then fetch only those IIDs. Quick approach with curl + jq (requires a personal access token with api scope and the project ID): - Export variables: export GITLAB_HOST=https://gitlab.com export GITLAB_TOKEN=YOUR_TOKEN export PROJECT_ID=123456 - Get IIDs for assigned, opened, label Ready: iids=$(curl -s --header "PRIVATE-TOKEN: $GITLAB_TOKEN" "$GITLAB_HOST/api/v4/projects/$PROJECT_ID/merge_requests?state=opened&scope=assigned_to_me&labels=Ready&per_page=100" | jq '.[].iid') - Fetch MR heads: git fetch origin 'refs/merge-requests/*/head:refs/remotes/origin/mr/*' - Create only the labeled branches: for iid in $iids; do git branch -f review/mr-$iid "refs/remotes/origin/mr/$iid"; done I’d still triage first and only bring down the few that need local runs, but this will restrict to “Ready”-labeled MRs.
