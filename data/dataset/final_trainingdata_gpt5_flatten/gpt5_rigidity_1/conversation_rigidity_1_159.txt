### Human: What about via the API?
### Assistant: Via the GitLab REST API (v4): - Create a merge request with reviewers: - POST /projects/:id/merge_requests - Include reviewer_ids[]=USER_ID for each reviewer. - Update an existing merge request’s reviewers: - PUT /projects/:id/merge_requests/:iid - Include reviewer_ids[]=USER_ID (this replaces the list with what you pass). Example (minimal): - POST …/merge_requests with: - title, source_branch, target_branch, reviewer_ids[]=123&reviewer_ids[]=456 - PUT …/merge_requests/:iid with: - reviewer_ids[]=123&reviewer_ids[]=789 Note: reviewer_ids expects user IDs (not usernames).
### Human: How do I require at least two approvals?
### Assistant: In the project: - Go to Settings > Merge requests (or Merge request approvals). - Set Approvals required to 2. - Optionally add approval rules (specify which users/groups can approve, per target branch). - If you use CODEOWNERS, you can enable “Require approval from Code Owners” so owners must approve for matching files. These settings enforce approvals separately from assigning reviewers.
