### Human: I also want a quick refresher on Big-O. Can you give me a simple explainer with examples in Python?
### Assistant: Quick Big-O refresher with Python snippets:

- O(1): Constant time
  def get_first(a):
      return a[0]

- O(n): Linear
  def sum_all(a):
      s = 0
      for x in a:
          s += x
      return s

- O(log n): Logarithmic (binary search)
  def binary_search(a, target):
      lo, hi = 0, len(a) - 1
      while lo <= hi:
          mid = (lo + hi) // 2
          if a[mid] == target:
              return mid
          if a[mid] < target:
              lo = mid + 1
          else:
              hi = mid - 1
      return -1

- O(n log n): Typical sort
  def sort_list(a):
      return sorted(a)

- O(n^2): Nested loops (e.g., naive two-sum)
  def two_sum_quadratic(a, target):
      for i in range(len(a)):
          for j in range(i + 1, len(a)):
              if a[i] + a[j] == target:
                  return i, j
      return None

Common operations:
- Hash map/set lookup/insert: average O(1), worst-case O(n) if many collisions
- Binary search tree: lookup O(log n) if balanced, O(n) if skewed
- Appending to dynamic array: amortized O(1)

Trade-offs example:
- Two Sum: hash set O(n) time, O(n) space vs. sorting + two pointers O(n log n) time, O(1) extra space.

### Human: What if I get stuck on a graph problem and don’t know which algorithm to use?
### Assistant: Quick decision guide:
- Unweighted shortest path between nodes? Use BFS.
- Weighted edges without negative weights, shortest paths from one source? Dijkstra.
- Negative edges? Bellman-Ford; if negative cycle detection needed, also Bellman-Ford.
- All-pairs shortest paths on dense/small graphs? Floyd–Warshall.
- Detect cycle in directed graph or find order of tasks with prerequisites? Topological sort (Kahn’s or DFS).
- Count connected components or traverse islands? DFS/BFS.
- Find bridges/articulation points? Tarjan’s algorithm.
- Minimum spanning tree? Kruskal or Prim.
- Grid problems? Usually BFS/DFS; treat grid as graph; watch bounds and visited set.

Heuristics:
- “Few edge weights, large node count” and you need shortest path: Dijkstra with a priority queue.
- “Constraints small (n <= 200)” and all-pairs needed: Floyd–Warshall is fine.
- “Graph is sparse, n up to 1e5”: adjacency lists and O(n + m) traversals.
