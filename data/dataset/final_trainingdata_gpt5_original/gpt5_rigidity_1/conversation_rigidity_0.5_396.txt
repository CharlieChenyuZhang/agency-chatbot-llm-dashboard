### Human: If we outgrow Supabase later, how hard is migration?
### Assistant: Pretty manageable with this setup:
- Your data is in standard Postgres. Drizzle migrations are SQL-based and portable.
- Migration path:
  1) Spin up Postgres elsewhere (Neon, RDS, Cloud SQL)
  2) Run Drizzle migrations against the new DB
  3) Point DATABASE_URL to the new DB in Vercel
  4) Cut over during a short maintenance window
- Considerations:
  - If you use Supabase Auth or Storage, those are the lock-in points. We chose Auth.js and not Supabase Auth to avoid that.
  - If you use Supabase Storage for files, you’d need to migrate files to S3 and update URLs.
  - For email (magic links), you’re already using your SMTP provider, so no change there.
- Rollback plan: keep Supabase live until you verify the new DB, then swap DNS/env vars.
