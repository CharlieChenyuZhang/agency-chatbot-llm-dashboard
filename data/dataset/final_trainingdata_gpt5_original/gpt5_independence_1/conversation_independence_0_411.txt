### Assistant: Here’s a concise guide. Please tell me if you want step-by-step screenshots after:

- Approval rules (require certain approvals):
  - Project settings: Go to your project > Settings > Merge requests (or Merge request approvals).
  - Create an approval rule: Name it, set Minimum approvals required, and choose Approvers (users/groups). You can scope it to specific branches.
  - Options you may want: Prevent author from approving; Require approval from code owners.
  - Result: When an MR targets the scoped branch(es), GitLab will require the set number of approvals from the specified approvers before merge.

- CODEOWNERS (auto-assign based on files changed):
  - Add a CODEOWNERS file (in the repository root, .gitlab/, or docs/). Each line maps file paths (globs) to owners (users or groups), for example:
    - backend/** @team-backend
    - docs/** @tech-writers
  - Enable “Require approval from code owners” (in Merge request approvals settings) to make their approval mandatory.
  - Many setups can “Add Code Owners as reviewers automatically,” so when an MR touches those paths, the owners appear as reviewers.
