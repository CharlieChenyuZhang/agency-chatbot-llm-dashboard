Compact Big-O Rules:
1) Ignore constants and low-order terms:
   - O(3n + 10) → O(n)
   - O(n² + n) → O(n²)

2) Sequential steps add:
   - do A (O(f(n))) then B (O(g(n))) → O(f(n) + g(n))

3) Nested loops multiply:
   - outer loop n, inner loop n → O(n²)
   - outer loop n, inner loop log n → O(n log n)

4) Most common complexities:
   - Array scan with a single loop: O(n)
   - Loop that halves n each time: O(log n)
   - Double nested loop over same range: O(n²)
   - Triple nested: O(n³)

5) Hash map (average case):
   - Insert, search, delete: O(1)
   - Beware: worst-case O(n), but usually not asked in detail.

Quick Example:
Code:
for i in range(n):
    for j in range(n):
        print(i, j)

- Outer loop: runs n times.
- Inner loop: runs n times for each outer iteration.
- Total operations ~ n * n = n² → O(n²).

### Assistant:
Here’s a slightly trickier one:

Code:
def example(arr):
    n = len(arr)
    i = 1
    while i < n:
        j = 0
        while j < i:
            print(arr[j])
            j += 1
        i *= 2

What’s the time complexity?

Step-by-step:

1) Outer loop (`i`):
   - i starts at 1 and doubles each time: 1, 2, 4, 8, … up to < n.
   - Number of iterations ≈ log₂n → O(log n).

2) Inner loop (`j`):
   - For each outer iteration, j runs from 0 to i-1.
   - So how many total prints?

   Let’s list per outer iteration:
   - When i = 1 → inner runs 1 time.
   - When i = 2 → inner runs 2 times.
   - When i = 4 → inner runs 4 times.
   - ...
   - Last iteration: i ≈ n/2 or n (depending exactly, but big-O wise ≈ n).

   Total work ≈ 1 + 2 + 4 + 8 + ... + n ≈ 2n - 1 → O(n)

3) Combine:
   - Although there’s a “while inside while,” total work isn’t O(n log n); it’s O(n), because the inner loop’s total work over all outer iterations forms a geometric series that sums to O(n).

Answer: O(n)

This pattern (i doubling, j running up to i) is one of those cases where naive “nested loop → multiply” fails; you have to reason about the total work across all iterations.

### Assistant:
Sure. Binary search is a key pattern you’ll use a lot in interviews.

Concept (for a sorted array):
- You repeatedly halve the search space:
  1) Look at the middle element.
  2) If it’s equal to target → found.
  3) If target is smaller → search left half.
  4) If target is larger → search right half.
- Time complexity: O(log n), because each step halves the remaining elements.

Typical iterative implementation (Python):

def binary_search(nums, target):
    left, right = 0, len(nums) - 1

    while left <= right:
        mid = (left + right) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            left = mid + 1
        else:
            right = mid - 1

    return -1  # not found

Key points:
- `left <= right` is a common condition; loops stops when search space is empty.
- Use `mid = left + (right - left) // 2` in some languages to avoid overflow (Python doesn’t need this, but it’s common practice).
- Remember that the array must be sorted.

Practice problem using binary search:
- LeetCode: Binary Search (easy).
- Then: Search Insert Position (easy).
- Then: Search in Rotated Sorted Array (medium) once you’re comfortable.
