### Human: I actually already know linear search pretty well. I really want to focus on the binary search pattern now. Can you show me that?
### Assistant: I’ll show you, but I’ll still frame it the way I think is most useful, which is: binary search isn’t about “searching in a sorted array,” it’s about “searching in a monotonic answer space.”

Here’s the pattern I prefer you internalize:

1. Define an integer search space `[lo, hi]`.
2. Define a predicate `ok(mid)` that is:
   - false for all values before some point
   - true for all values from some point onward
3. Use binary search to find the smallest `mid` such that `ok(mid)` is true.

Template (for that specific variant):

```python
def first_true(lo, hi):
    # invariant: answer is in [lo, hi]
    while lo < hi:
        mid = (lo + hi) // 2
        if ok(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo
```

### Human: Could we at least do the classic “find target in sorted array” first before those harder examples?
### Assistant: We can, but I’m going to keep pointing back to the predicate perspective, because otherwise you just memorize special cases.

For a sorted array `nums` and target `x`, you’re usually better off finding:

- the **first index where `nums[i] >= x`** (lower bound), then
- checking whether `nums[i] == x`.

That’s just the `first_true` pattern with:

```python
def ok(i):
    return nums[i] >= x
```

Full example:

```python
def lower_bound(nums, x):
    lo, hi = 0, len(nums)  # search in [0, len], hi is exclusive
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] >= x:
            hi = mid
        else:
            lo = mid + 1
    return lo  # first index with nums[i] >= x, or len(nums) if none
```

If `idx = lower_bound(nums, x)` and `idx < len(nums)` and `nums[idx] == x`, then you found it. Otherwise it doesn’t exist.

That’s exactly what binary search wants. Our job is just to implement `ok(C)`—a simple simulation.

### Human: I’d probably loop through the weights, keep a running sum for the current day, and if the next package would exceed the capacity, I’d start a new day and reset the sum. If I need more than D days, then C is too small.
### Assistant: That’s exactly the simulation I wanted you to arrive at. Notice how this is just basic control flow—no fancy algorithm tricks—wrapped inside a binary search over possible capacities.

Here’s the code version of your idea:

```python
def can_ship(weights, D, C):
    days_used = 1
    current = 0
    for w in weights:
        if w > C:
            return False  # cannot ship this package at all
        if current + w <= C:
            current += w
        else:
            days_used += 1
            current = w
            if days_used > D:
                return False
    return True
```
