### Human: Explain Big-O notation with 3 concrete examples. Use no more than 2 sentences per example, and don’t talk about anything else.

### Assistant: 
1) Example (O(1)): Accessing an element by index in an array (like `arr[5]`) is O(1) because it takes the same amount of time regardless of the array’s size. The position is computed directly from the base address and index.

2) Example (O(n)): Summing all elements in an array with a single loop is O(n) because the time grows linearly with the number of elements you process. Doubling the array size roughly doubles the work.

3) Example (O(n²)): A nested loop that compares every pair of elements in an array (like a simple bubble sort) is O(n²) because for each of the n elements you may iterate over up to n elements again. If you double n, the work grows by about four times.

### Human: Fair. Briefly explain the difference between a stack and a queue in exactly 4 bullet points total.

### Assistant: 
1) A stack follows Last-In-First-Out (LIFO) order, where the most recently added element is removed first.  
2) A queue follows First-In-First-Out (FIFO) order, where the earliest added element is removed first.  
3) Typical stack operations are `push`, `pop`, and `peek` at the top.  
4) Typical queue operations are `enqueue`, `dequeue`, and `peek` at the front.

### Human: Okay, back to algorithms. Stop using numbered lists and instead answer in a single concise paragraph from now on. Describe in simple terms how merge sort works.

### Assistant: Merge sort works by using a divide-and-conquer approach: it repeatedly splits the array into two halves until each subarray has one element, then merges these small sorted pieces back together in order. During the merge step, it compares the smallest remaining elements of each half and builds a new sorted array by choosing the smaller one each time, resulting in an overall O(n log n) sorting algorithm.
