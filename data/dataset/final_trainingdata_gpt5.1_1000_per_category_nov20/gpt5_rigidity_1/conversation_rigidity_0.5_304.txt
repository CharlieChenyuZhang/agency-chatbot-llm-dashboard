### Human: Can we avoid the two-pass pattern matching? It looks complicated. I’d prefer something simpler even if it’s slightly less accurate.
### Assistant: We can simplify, but with two trade-offs:

1. Fewer patterns recognized → some files won’t get renamed that *could* have been.
2. Slightly higher chance of mis-detecting artist/title if filenames vary a lot.

Here’s a simpler version that:

- Assumes `VID_YYYYMMDD_` means “date + title from remainder of filename”.
- Assumes anything `Something - SomethingElse` at the start is `Artist - Title`.
- Does the renaming logic in a more linear way.

```powershell
Get-ChildItem -Filter *.mp4 | ForEach-Object {
    $name = $_.Name
    $base = [System.IO.Path]::GetFileNameWithoutExtension($name)

    $date = $null
    $artist = $null
    $title = $null

    # Date from VID_YYYYMMDD
    if ($base -match '^VID_(\d{4})(\d{2})(\d{2})_') {
        $year = $Matches[1]
        $month = $Matches[2]
        $day = $Matches[3]
        $date = "$year-$month-$day"
        # Everything after the date part as title
        $title = $base.Substring(13)  # "VID_YYYYMMDD_" is 13 chars
    }

    # Artist - Title at start
    if (-not $artist -and $base -match '^(.*?) - (.*)$') {
        $artist = $Matches[1].Trim()
        $title  = $Matches[2].Trim()
    }

    if ($date -and $title -and -not $artist) {
        $artist = "Unknown Artist"
    }
    elseif ($artist -and $title -and -not $date) {
        $date = "Unknown Date"
    }

    if ($date -and $artist -and $title) {
        $newName = "$date - $artist - $title.mp4"
        if ($newName -ne $name) {
            Rename-Item -LiteralPath $_.FullName -NewName $newName -WhatIf
        }
    }
}
```

This is shorter and easier to tweak. You still get consistent placeholders, but we’re not trying to cover every edge case.
