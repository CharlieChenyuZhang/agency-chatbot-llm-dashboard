### Human: I'm using GitLab. I want a command-line way to check out all merge requests assigned to me locally.

### Assistant: For GitLab, there are two good approaches:

1. Using the official `glab` CLI (simpler).
2. Using plain `curl` + `git` + GitLab API (more manual).

I’ll outline both; you can pick.

#### Option 1: Using `glab` (recommended)

1. Install `glab`:
   - macOS (Homebrew):  
     ```bash
     brew install glab
     ```
   - Linux (Debian/Ubuntu, via script):  
     ```bash
     curl -s https://raw.githubusercontent.com/profclems/glab/trunk/scripts/install.sh | sudo bash
     ```
   - Or see: https://gitlab.com/gitlab-org/cli

2. Authenticate:
   ```bash
   glab auth login
   ```
   Follow the prompts (it will ask for a personal access token).

3. From inside your project repo, list MRs assigned to you:
   ```bash
   glab mr list --assignee @me
   ```

4. Check out a specific MR:
   ```bash
   glab mr checkout <iid>
   ```
   `<iid>` is the internal ID from the list, e.g. `!42` → `42`.

5. If you want to check out *all* assigned MRs in a loop:
   ```bash
   for iid in $(glab mr list --assignee @me --no-header --format "{{.IID}}"); do
     echo "Checking out MR !${iid}"
     glab mr checkout "$iid"
   done
   ```

### Human: I'd rather not install glab. Show me the curl + GitLab API approach. I'm on macOS.

### Assistant: Understood. Here’s a minimal approach using `curl`, `jq`, and `git`.

Assumptions:
- You’re in a cloned GitLab repo directory (HTTP or SSH remote is fine).
- You have:
  - A personal access token with `api` scope.
  - Your GitLab base URL (e.g. `https://gitlab.com` or `https://gitlab.yourcompany.com`).

#### 1. Set up environment variables

```bash
export GITLAB_URL="https://gitlab.com"             # change if self-hosted
export GITLAB_TOKEN="YOUR_PERSONAL_ACCESS_TOKEN"   # keep this secret
```

You also need the project ID:

```bash
curl --header "PRIVATE-TOKEN: $GITLAB_TOKEN" \
     "$GITLAB_URL/api/v4/projects?search=$(basename $(pwd))" | jq '.[0].id'
```

Take the number returned and export it:

```bash
export GITLAB_PROJECT_ID=123456   # replace with actual ID
```

#### 2. List assigned merge requests (for confirmation)

```bash
curl --header "PRIVATE-TOKEN: $GITLAB_TOKEN" \
  "$GITLAB_URL/api/v4/projects/$GITLAB_PROJECT_ID/merge_requests?assignee_id=me&state=opened" \
  | jq '.[] | {iid, title, source_branch}'
```

#### 3. Script to fetch and check out each MR

From inside the repo:

```bash
curl --header "PRIVATE-TOKEN: $GITLAB_TOKEN" \
  "$GITLAB_URL/api/v4/projects/$GITLAB_PROJECT_ID/merge_requests?assignee_id=me&state=opened&per_page=100" \
  | jq -r '.[] | "\(.iid) \(.source_branch)"' \
  | while read iid branch; do
      echo "Processing MR !${iid} (branch: ${branch})"
      git fetch origin "${branch}:${branch}" || continue
      echo "Checked out local branch: ${branch}"
    done
```

This will:
- For each assigned MR:
  - Fetch its `source_branch` from `origin` into a local branch of the same name.
- It does *not* auto-switch your working directory to each branch; it just creates/updates them. You can then `git checkout <branch>` as needed.

If you prefer to actually *visit* each branch one by one, we can tweak the script.

Try the `curl` listing command first. If it fails or returns an error, paste the error message and we’ll debug it.

```bash

import urllib.parse
```

If you don’t want to use Python, a simpler but more manual way:

1. Take your namespace/project path from the URL, e.g. `group/subgroup/project`.
2. URL-encode the `/` as `%2F`: `group%2Fsubgroup%2Fproject`.
3. Call:

```bash

  "$GITLAB_URL/api/v4/projects/group%2Fsubgroup%2Fproject"
```

If that returns your project JSON, note the `"id"` field and set:

