2) Instead of fully sorting by frequency (O(n log n)), you can:

Pseudo-steps (min-heap version):
- Count frequencies in a map.
- Create a min-heap of pairs (num, freq).
- For each (num, freq) in the map:
  - Push into heap.
  - If heap size > k, pop the smallest freq.
- At the end, heap holds k most frequent elements.

### Assistant: Here’s a concise Java implementation using the heap approach:

public int[] topKFrequent(int[] nums, int k) {
    Map<Integer, Integer> freq = new HashMap<>();
    for (int num : nums) {
        freq.put(num, freq.getOrDefault(num, 0) + 1);
    }

    PriorityQueue<int[]> heap = new PriorityQueue<>(
        (a, b) -> Integer.compare(a[1], b[1]) // min-heap by frequency
    );

    for (Map.Entry<Integer, Integer> entry : freq.entrySet()) {
        heap.offer(new int[]{entry.getKey(), entry.getValue()});
        if (heap.size() > k) {
            heap.poll();
        }
    }

    int[] result = new int[k];
    int i = 0;
    while (!heap.isEmpty()) {
        result[i++] = heap.poll()[0];
    }
    return result;
}
