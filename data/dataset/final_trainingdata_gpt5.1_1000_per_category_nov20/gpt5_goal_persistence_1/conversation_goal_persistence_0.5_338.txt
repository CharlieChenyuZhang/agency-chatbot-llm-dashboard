### Assistant:
Sure. A 502 with Nginx typically means it’s configured as a **reverse proxy** to something upstream that isn’t running, instead of just serving static files.

Let’s change it to a **pure static config**.

Assuming:
- Your site files are in: `/var/www/blog/public`
- Your domain is: `yourdomain.com`

1. Open your Nginx server block for that domain, typically:
   - `/etc/nginx/sites-available/yourdomain.com` (or `default` for a single site)

2. Replace its contents with something like:

```nginx
server {
    listen 80;
    server_name yourdomain.com www.yourdomain.com;

    root /var/www/blog/public;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }

    access_log /var/log/nginx/yourdomain.access.log;
    error_log  /var/log/nginx/yourdomain.error.log;
}
```

3. Test and reload:

```bash
sudo nginx -t
sudo systemctl reload nginx
```

4. Ensure file permissions:

```bash
sudo chown -R www-data:www-data /var/www/blog/public
sudo find /var/www/blog/public -type d -exec chmod 755 {} \;
sudo find /var/www/blog/public -type f -exec chmod 644 {} \;
```

After that, visiting `http://yourdomain.com/` should serve `index.html` from `public/`.

If you’re still getting a 502, could you paste your current Nginx server block config (sanitizing any sensitive IPs/hosts)?
