### Human: Checkout merge requests assigned to me

### Assistant: To check out merge requests (MRs) assigned to you locally, you generally:

1. Find the MR ID(s) assigned to you.
2. Fetch the MR ref.
3. Check out a local branch tracking that ref.

Assuming GitLab and a local `git` clone:

**1. List MRs assigned to you (web UI):**
- Go to your GitLab project.
- In the left sidebar: **Merge requests → Assigned to you**.
- Note the MR ID, e.g. `!123`.

**2. Check out the MR locally (GitLab default refs):**
From your project repo:

```bash
git fetch origin merge-requests/123/head:mr-123
git checkout mr-123
```

Replace `123` with the MR ID (without the `!`).

### Human: Yeah, it’s GitLab, and I just want a simple command that checks out the first MR assigned to me. Can we script that?

### Assistant: Yes, you can script this using the GitLab API plus `git`. High level:

1. Call the API to get MRs assigned to you.
2. Take the first one (e.g., by `created_at`).
3. `git fetch` its MR ref and `git checkout` a local branch.

Here’s a Bash example using GitLab’s REST API and `jq`:

Prereqs:
- You’re in your project directory (already cloned).
- You have:
  - `GITLAB_TOKEN` (personal access token with `api` scope),
  - `GITLAB_BASE_URL` (e.g. `https://gitlab.com` or your self-hosted URL),
  - `GITLAB_PROJECT_PATH` (e.g. `mygroup/myproject`).
- `jq` installed.

```bash
#!/usr/bin/env bash
set -euo pipefail

: "${GITLAB_TOKEN:?Set GITLAB_TOKEN}"
: "${GITLAB_BASE_URL:?Set GITLAB_BASE_URL (e.g. https://gitlab.com)}"
: "${GITLAB_PROJECT_PATH:?Set GITLAB_PROJECT_PATH (e.g. mygroup/myproject)}"

PROJECT_ENCODED=$(python3 - <<EOF
import urllib.parse
print(urllib.parse.quote("${GITLAB_PROJECT_PATH}", safe=''))
EOF
)

MR_JSON=$(
  curl -sS --header "PRIVATE-TOKEN: ${GITLAB_TOKEN}" \
    "${GITLAB_BASE_URL}/api/v4/projects/${PROJECT_ENCODED}/merge_requests?state=opened&scope=assigned_to_me&order_by=created_at&sort=asc&per_page=1"
)

MR_IID=$(echo "$MR_JSON" | jq '.[0].iid')
if [ "$MR_IID" = "null" ] || [ -z "$MR_IID" ]; then
  echo "No open MRs assigned to you."
  exit 0
fi

BRANCH="mr-${MR_IID}"

echo "Checking out MR !${MR_IID} into branch ${BRANCH}..."

git fetch origin "merge-requests/${MR_IID}/head:${BRANCH}"
git checkout "${BRANCH}"

echo "Done."
```

### Human: `git ls-remote origin | grep merge-requests` shows lines like `refs/merge-requests/12/head` and `refs/merge-requests/13/head`, but nothing for 45. Most of my assigned MRs are from forks.

### Assistant: That explains it: your GitLab only exposes MR refs for some MRs (likely those whose source branch is in the same project). For fork-based MRs, you typically need to:

1. Add the contributor’s fork as a remote.
2. Fetch their branch.
3. Check it out.

The API response for an MR includes `source_project_id` and `source_branch`. For fork-based MRs:

- `source_project_id` ≠ your project id.
- You’d have to fetch from that source project’s Git URL.

A more complete script would:

1. Look up the MR.
2. If `source_project_id` = target project id:
   - Use `git fetch origin "merge-requests/IID/head:BRANCH"`.
3. Otherwise (fork):
   - Get the source project’s SSH URL from `/projects/:id`.
   - Create a temporary remote (e.g. `mr-<iid>`).
   - `git fetch` the `source_branch` from that remote.
   - Check it out.

Conceptually:

```bash
# 1) Get MR info
MR=$(
  curl -sS --header "Authorization: Bearer ${GITLAB_TOKEN}" \
  "$GITLAB_BASE_URL/api/v4/projects/${PROJECT_ENCODED}/merge_requests/${MR_IID}"
)

SOURCE_PROJECT_ID=$(echo "$MR" | jq '.source_project_id')
TARGET_PROJECT_ID=$(echo "$MR" | jq '.target_project_id')
SOURCE_BRANCH=$(echo "$MR" | jq -r '.source_branch')

if [ "$SOURCE_PROJECT_ID" -eq "$TARGET_PROJECT_ID" ]; then
  git fetch origin "merge-requests/${MR_IID}/head:mr-${MR_IID}"
  git checkout "mr-${MR_IID}"
else
  # 2) Get source project SSH URL
  SRC_PROJECT=$(curl -sS --header "Authorization: Bearer ${GITLAB_TOKEN}" \
    "$GITLAB_BASE_URL/api/v4/projects/${SOURCE_PROJECT_ID}")
  SRC_SSH_URL=$(echo "$SRC_PROJECT" | jq -r '.ssh_url_to_repo')

  REMOTE_NAME="mr-${MR_IID}"
  if ! git remote | grep -q "^${REMOTE_NAME}\$"; then
    git remote add "$REMOTE_NAME" "$SRC_SSH_URL"
  fi

  git fetch "$REMOTE_NAME" "${SOURCE_BRANCH}:mr-${MR_IID}"
  git checkout "mr-${MR_IID}"
fi
```

This is a bit more involved, but it would handle forks.

### Assistant: Here’s a compact workflow you can use without the API.

#### 1) Same-project MRs (source branch in the same repo)

From GitLab UI:
- Go to **Merge requests → Assigned to you**.
- Open the MR, note its IID (e.g. `!45` → `45`).

In your local repo:

```bash
MR=45
BRANCH="mr-$MR"
git fetch origin "merge-requests/$MR/head:$BRANCH"
git checkout "$BRANCH"
```

If you like, turn this into a tiny shell function:

```bash
mrco() {  # usage: mrco 45
  local mr="$1"
  git fetch origin "merge-requests/$mr/head:mr-$mr" && git checkout "mr-$mr"
}
```

#### 2) Fork-based MRs

From the MR page in GitLab:
- Find the source project and branch, e.g.  
  `someuser/myproject` on branch `feature/foo`.
- Copy the SSH URL of the source project, e.g. `git@gitlab.internal:someuser/myproject.git`.

In your local repo:

```bash
MR=45
REMOTE="mr-$MR"
SRC_SSH_URL="git@gitlab.internal:someuser/myproject.git"
SRC_BRANCH="feature/foo"

git remote add "$REMOTE" "$SRC_SSH_URL"   # only once per MR
git fetch "$REMOTE" "$SRC_BRANCH:mr-$MR"
git checkout "mr-$MR"
```

After you’re done reviewing, you can optionally clean up:

```bash
git branch -D "mr-$MR"
git remote remove "$REMOTE"
```

This avoids any API calls and should work consistently given your environment. If you want, you can combine these into a small script that prompts you for:
- MR number,
- and, if needed, the fork URL + branch,  
but that part will still be manual lookup from the UI.
