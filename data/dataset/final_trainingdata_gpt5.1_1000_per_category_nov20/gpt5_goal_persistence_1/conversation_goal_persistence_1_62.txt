5. **Suggested reviewers / Code owners (if configured)**
   - If **CODEOWNERS** and/or suggested reviewers are configured, GitLab can propose appropriate reviewers based on the files changed.

That’s the core flow: open MR → use the **Reviewers** section in the sidebar or quick actions → optionally leverage approval rules and code owners.

**3. Implement `.ci/check_review_policy.py`**

High-level logic (pseudo-code):

```python
import os
import sys
import requests
import yaml

GITLAB_API = os.environ.get("CI_API_V4_URL")
PROJECT_ID = os.environ.get("CI_PROJECT_ID")
MR_IID = os.environ.get("CI_MERGE_REQUEST_IID")
TOKEN = os.environ.get("REVIEW_POLICY_TOKEN")  # personal/project access token

if not MR_IID:
    print("Not a merge request pipeline; skipping.")
    sys.exit(0)

with open(".ci/review-teams.yml") as f:
    cfg = yaml.safe_load(f)

backend_users = set(cfg["backend"])
frontend_users = set(cfg["frontend"])

headers = {"PRIVATE-TOKEN": TOKEN}

# Get approvals for this MR
url = f"{GITLAB_API}/projects/{PROJECT_ID}/merge_requests/{MR_IID}/approvals"
resp = requests.get(url, headers=headers)
resp.raise_for_status()
data = resp.json()

approved_by = {a["user"]["username"] for a in data.get("approved_by", [])}

has_backend = bool(approved_by & backend_users)
has_frontend = bool(approved_by & frontend_users)

if not has_backend or not has_frontend:
    print("Review policy not satisfied:")
    print(f" - Has backend approver: {has_backend}")
    print(f" - Has frontend approver: {has_frontend}")
    sys.exit(1)

print("Review policy satisfied.")
```
