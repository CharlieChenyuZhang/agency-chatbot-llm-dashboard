Problem:

Let’s go step by step:

2) Brainstorm approaches
Common ideas:

- Sort then scan.
- Use bitwise XOR.

Each has trade-offs (time/space). The interviewer’s hint “linear time and constant extra space” is important.

3) Choose an approach
- Hash map: O(n) time, O(n) space → violates constant extra space.
- Sort: O(n log n) time, O(1) or O(log n) space → violates linear time.
- XOR: O(n) time, O(1) space → meets both constraints.

Key property:
- x ^ x = 0
- x ^ 0 = x
- XOR is commutative and associative

So if you XOR all elements, pairs cancel out, leaving the single number.

4) Code in Python (what I’d expect from you):

def single_number(nums):
    result = 0
    for x in nums:
        result ^= x
    return result

5) Edge cases:
- Single-element array: [5] → result = 5.
- Repeated negatives: [2, -1, 2] → result = -1.
- Larger arrays.

### Assistant: That’s a good constraint; we’ll aim for intuition and stop before it gets frustrating.

Intuition for O(n log n) LIS:
- Maintain an array `tails`, where `tails[k]` is the smallest possible tail value of an increasing subsequence of length `k+1` we’ve seen so far.
- Iterate over nums:
  - For each x:
    - Use binary search on `tails` to find the first index i where tails[i] ≥ x.
    - If such i exists, set tails[i] = x (we found a “better” tail for length i+1).
    - If not, append x to `tails` (we extended the longest subsequence).
- The length of `tails` at the end is the length of the LIS.

Example with nums = [10,9,2,5,3,7,101,18]:
- Start: tails = []
- x=10 → tails=[10]
- x=9  → replace first ≥9 → [9]
- x=2  → [2]
- x=5  → append → [2,5]
- x=3  → replace first ≥3 → [2,3]
- x=7  → append → [2,3,7]
- x=101→ append → [2,3,7,101]
- x=18 → replace first ≥18 → [2,3,7,18]
Length of tails = 4 → LIS length is 4.

Key point:
- tails does NOT store an actual subsequence; it stores best “candidates” for each length.
- Binary search on tails → O(log n) per element → O(n log n) total.
