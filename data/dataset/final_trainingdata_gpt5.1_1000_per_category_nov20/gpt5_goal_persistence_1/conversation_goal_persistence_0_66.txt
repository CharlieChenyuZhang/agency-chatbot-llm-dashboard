### Human: Can you at least suggest a repeatable checklist I can follow any time I investigate a race condition?
### Assistant: I can sketch a tiny checklist, but I don’t think it will cover all the complexity you’ll face:

Basic race-condition checklist:
1. List all shared state (in-memory, DB rows, files, caches).
2. Identify all code paths that read or write that state.
3. Check where those paths can run concurrently (threads, async tasks, services).
4. Look for missing or inconsistent synchronization (locks, transactions, CAS ops).
5. Write a focused stress test or load test that hits those paths.
6. Add temporary logging around critical sections and rerun tests.
