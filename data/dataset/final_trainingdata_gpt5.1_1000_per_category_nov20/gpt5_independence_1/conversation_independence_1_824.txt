Introduction (draft):

Large language models (LLMs) have become the foundation of modern natural language processing, achieving state-of-the-art results on a wide range of benchmarks and tasks. However, many real-world applications require deploying these models in specialized domains such as law, medicine, software engineering, or finance, where data distributions and information needs differ substantially from those of the web-scale corpora used during pretraining. In these settings, practitioners often have access to a small amount of labeled data, alongside a much larger pool of unlabeled domain text such as documents, articles, or logs. The central question we address in this work is: how can we most effectively exploit these heterogeneous domain resources to adapt powerful but generic LLMs to specialized tasks?

A common approach is to fine-tune all or most of the model’s parameters on the available labeled data. While effective when labels are plentiful, full fine-tuning is computationally expensive and prone to overfitting in low-resource regimes. Parameter-efficient fine-tuning (PEFT) methods such as adapters, LoRA, and prompt tuning mitigate these issues by updating only a small fraction of the model’s parameters. Yet, in typical usage, PEFT operates purely on the labeled dataset and does not explicitly leverage the often much larger unlabeled domain corpus. In parallel, retrieval-augmented methods augment the model’s context with externally retrieved documents at inference time, improving factuality and grounding. However, these methods usually treat the base model as fixed and learn retrieval in a way that is weakly coupled, if at all, to the downstream adaptation process.

We argue that for domain-specific tasks with limited labels but abundant unlabeled text, we should both (i) retain the computational benefits of PEFT, and (ii) integrate retrieval more tightly into the adaptation process. To this end, we propose Domain Memory Adapters, a framework that jointly learns a domain memory and parameter-efficient adapters for a pre-trained LLM. Given a large unlabeled corpus for each domain, we automatically construct a memory of text chunks and build an index that supports efficient retrieval. A retrieval encoder is trained to select memory entries that are most useful for solving the downstream task, while lightweight adapters inside the LLM are trained to condition on the retrieved content. Crucially, retrieval and adaptation are optimized under a unified objective over a small labeled dataset, ensuring that the memory is used in a way that directly supports task performance.

Our approach offers three key advantages. First, it exploits unlabeled domain text at scale without incurring the cost of full domain pretraining, by compressing this text into a task-aware memory. Second, it maintains the efficiency and parameter frugality of PEFT, enabling adaptation of large models under realistic compute budgets. Third, by jointly learning retrieval and adapters, it encourages synergy between what is retrieved and how it is used, leading to more effective domain specialization than either component alone.

We evaluate Domain Memory Adapters on specialized tasks across four domains: legal, biomedical, programming, and finance. In all settings, our method outperforms strong baselines, including full fine-tuning, standard PEFT, and retrieval-augmented generation with fixed adapters, particularly in low-resource regimes. Moreover, we find that our joint framework yields improved robustness under domain shift and noisy memory, suggesting that learning to retrieve and adapt in tandem produces more reliable domain-specialized LLMs.

In summary, this work makes the following contributions:
- We introduce a unified framework that combines domain memory construction, retrieval learning, and parameter-efficient adaptation for LLMs.
- We develop a joint training objective that aligns retrieval with downstream task performance while preserving computational efficiency.
- We provide an extensive empirical study across four specialized domains, demonstrating consistent gains over strong baselines and improved robustness in low-resource and shifted-domain scenarios.

Method (draft):

3 Method

We describe Domain Memory Adapters, a framework for adapting a pre-trained language model to domain-specific tasks by jointly learning a domain memory, a retrieval mechanism, and parameter-efficient adapters. We first formalize the problem, then detail how we construct the domain memory, integrate retrieved content into the model, and train the system end-to-end.

3.1 Problem Formulation

Let f_θ denote a pre-trained language model with parameters θ, which we treat as largely frozen during adaptation. We are given a set of domains D. For each domain d ∈ D, we assume access to (i) a small labeled dataset L_d = {(x_i, y_i)}_i, where x_i is an input (e.g., a question, a document, or a code snippet) and y_i is a task-specific label or target; and (ii) a large unlabeled corpus U_d = {u_j}_j of domain text (e.g., documents, articles, or posts). Our goal is to adapt f_θ to perform well on the target task in each domain d, using L_d and U_d, under realistic compute constraints.

We introduce two sets of learnable components shared across or specialized to domains: (i) adapter parameters φ, which define lightweight modules inserted into the base model; and (ii) retrieval parameters ψ, which define how we embed and score elements of a domain memory M_d constructed from U_d. At inference time, given an input x from domain d, the model retrieves relevant memory entries from M_d and conditions the adapted language model f_{θ,φ} on both x and the retrieved content to produce predictions ŷ.

3.2 Domain Memory Construction

For each domain d, we construct a memory M_d by processing the unlabeled corpus U_d into a set of text chunks suitable for retrieval.

Chunking and preprocessing  
We first segment each document u ∈ U_d into overlapping spans of up to T tokens (e.g., T = 512), using a sliding window with stride S < T (e.g., S = 256). This yields a collection of candidate chunks C_d = {c_k}_k. We optionally apply simple filtering heuristics (e.g., minimum length, language detection, or domain-specific keyword checks) to remove non-informative or out-of-domain chunks.

Memory representations  
We represent each chunk c_k by an embedding vector e_k ∈ ℝ^m. To balance quality and efficiency, we use a dual-encoder architecture: a text encoder g_ψ(·) parameterized by ψ that maps chunks to embeddings, and a separate encoder h_ψ(·) that maps queries (inputs x) to the same embedding space. During initialization, g_ψ and h_ψ can be seeded from a pre-trained sentence encoder or from the base model’s hidden states.

We compute e_k = g_ψ(c_k) for all chunks and store them along with their raw text in the domain memory:
M_d = {(c_k, e_k)}_k.

Indexing  
To support efficient retrieval at training and test time, we build an approximate nearest neighbor index (e.g., using FAISS) over {e_k}_k for each domain. This index allows us to retrieve the top-K memory entries given a query embedding in sub-linear time.

3.3 Retrieval-Conditioned Adapters

We adapt the base language model f_θ with lightweight adapters and expose a mechanism to condition predictions on retrieved memory.

Adapter architecture  
We insert small bottleneck adapters into a subset of transformer layers of f_θ. Each adapter consists of a down-projection W_down ∈ ℝ^{d×r}, a nonlinearity σ, and an up-projection W_up ∈ ℝ^{r×d}, where d is the hidden size and r ≪ d is the adapter bottleneck dimension. Given a hidden state h at a layer, the adapter outputs:
h' = h + W_up σ(W_down h).

The collection of all adapter parameters constitutes φ. During domain adaptation, we keep θ fixed and update only φ (and the retrieval parameters ψ).

Conditioning on retrieved memory  
Given an input x from domain d, we obtain a query embedding q = h_ψ(x) and retrieve the top-K nearest memory entries {(c_k, e_k)}_{k=1}^K from M_d using the index. We then form a retrieval-augmented input sequence by concatenating the input with the retrieved chunks:

x̃ = [x; SEP; c_1; SEP; …; c_K],

where SEP is a special separator token. To avoid excessive context length, we cap the total number of tokens from retrieved chunks and optionally truncate or rank them by a learned score.

In addition to simple concatenation, we introduce a lightweight gating mechanism that allows the model to modulate its reliance on retrieved content. Specifically, we add a scalar gate g ∈ [0, 1] at each layer that scales the contribution of adapter outputs conditioned on the positions corresponding to retrieved tokens. This gate is parameterized by a small neural network that takes as input summary statistics of the retrieved embeddings (e.g., their mean and variance) and the current hidden state.

During forward propagation, f_{θ,φ} processes x̃ as usual, with adapters active in the selected layers. The presence of retrieved chunks in the context, combined with adapter specialization, allows the model to incorporate domain-specific information stored in M_d.

3.4 Joint Training Objective

We train the retrieval encoders and adapters jointly so that retrieval focuses on memory entries that directly improve task performance.

Task loss  
For supervised domain adaptation, we define a task loss L_task over the labeled dataset L_d. For classification or span selection tasks, L_task is typically cross-entropy between the model’s predictions and ground-truth labels. For each (x, y) ∈ L_d, we construct x̃ with retrieved chunks as described above, run f_{θ,φ}(x̃), and compute the loss against y.

Retrieval supervision  
To encourage meaningful retrieval beyond what is implicitly learned through backpropagation from L_task, we add an auxiliary retrieval loss. We adopt a contrastive learning objective: for each labeled example (x, y), we treat the retrieved chunks that lead to correct predictions as positives and randomly sampled or hard-negative chunks from M_d as negatives. Concretely, given a query embedding q and a set of candidate memory embeddings {e_k}, we define similarity scores s_k = q⊤ e_k / τ, where τ is a temperature parameter, and optimize an InfoNCE-style loss:

L_ret = − log exp(s_pos) / (exp(s_pos) + Σ_neg exp(s_neg)),

where s_pos is the similarity to a positive chunk and the sum runs over sampled negatives. In practice, we approximate positives either via the top-ranked retrieved chunks when the model predicts y correctly or via heuristics based on lexical overlap or task-specific signals.

Joint objective and training procedure  
The overall objective combines the task and retrieval losses:

L_total = L_task + λ L_ret,

where λ controls the strength of retrieval regularization. We choose λ via validation on a held-out portion of L_d.

Training proceeds in two stages:

1. Memory pretraining. We warm up the retrieval encoders g_ψ and h_ψ on U_d using unsupervised or weakly supervised objectives, such as masked language modeling with chunk-level contrastive learning, to provide reasonable initial embeddings.

2. Joint adaptation. We freeze the base model parameters θ and optimize adapters φ and retrieval parameters ψ jointly on L_d, minimizing L_total. During this stage, every training step involves (i) encoding the input x, (ii) retrieving top-K memory entries from M_d, (iii) constructing x̃, (iv) running f_{θ,φ}(x̃), and (v) updating φ and ψ via backpropagation.

3.5 Inference

At test time, for a new input x from domain d, we compute its query embedding q, retrieve the top-K memory chunks from M_d, construct x̃, and run the adapted model f_{θ,φ} to obtain predictions. No gradient updates occur at inference, and the additional computational overhead arises only from retrieval and slightly increased sequence length, while parameter count remains close to that of the base model.

Each example consists of a natural language query (e.g., a description of a function) and candidate code snippets, with labels indicating the correct snippet. We use the corpus of code and related descriptions as the unlabeled source for constructing the domain memory.

Finance (FiQA Sentiment)  
For the finance domain, we use the FiQA sentiment dataset, which contains financial news headlines and microblog entries annotated with sentiment labels (e.g., negative, neutral, positive). We define a 3-way sentiment classification task over these labels. We augment the unlabeled corpus with additional financial news articles and company reports to build a richer domain memory.

For all domains, we standardize preprocessing (tokenization, truncation) and ensure comparable low-resource regimes by sampling similar numbers of labeled examples (e.g., 1k and 5k) where dataset sizes permit.

4.2 Base Models and Parameter-Efficient Adaptation

We adopt a pre-trained transformer-based language model as our base model f_θ. In our main experiments, we use an open-weight decoder-only LLM with approximately 7–13B parameters, which provides a strong backbone for all four domains while remaining tractable for experimentation.

Adapters  
We insert bottleneck adapters into a subset of transformer layers (e.g., every other layer) with bottleneck dimension r (e.g., r = 64). All adapter parameters constitute φ and are learned during domain adaptation, while θ remains fixed. We also experiment with LoRA-style low-rank updates in a subset of attention projections as an alternative PEFT configuration and report the best-performing setting.

4.3 Baselines

Full fine-tuning  
We fine-tune all parameters θ of the base model on each domain’s labeled dataset L_d, without using unlabeled text U_d for domain memory. This represents an upper-bound style baseline in terms of flexibility but is computationally more expensive.

PEFT-only (Adapters / LoRA)  
We apply adapters or LoRA modules to the base model and fine-tune only these parameter-efficient components on L_d, with no retrieval or use of U_d. This baseline isolates the contribution of parameter-efficient adaptation alone.

We train a retrieval encoder on U_d (e.g., using contrastive learning or existing retrieval benchmarks) and use it to retrieve top-K documents for each input x at inference time. The retrieved documents are concatenated to the input and fed to a frozen or lightly tuned base model. The retrieval and language model are not jointly optimized for the downstream task.

Retrieval + adapters without joint training

There is no auxiliary retrieval loss during adapter training, so retrieval is not directly optimized for task performance.

Our method: Domain Memory Adapters  
Our proposed approach jointly learns domain memories, retrieval encoders, and adapters under the unified objective described in Section 3, leveraging both L_d and U_d.

4.4 Training Details

For all methods, we use the same tokenization and maximum sequence length (e.g., 1024 tokens). We optimize with AdamW, using a learning rate tuned per method from a small grid (e.g., {1e−5, 3e−5, 1e−4}) on the validation set. We train models for a fixed number of epochs (e.g., 3–10, depending on dataset size) with early stopping based on validation performance.

For Domain Memory Adapters, we construct domain memories with chunk size T = 512 and stride S = 256, and retrieve K documents per input (e.g., K = 5). We pretrain the retrieval encoders on U_d for a small number of epochs with an unsupervised objective, then perform joint training on L_d with the combined loss L_total. We set the retrieval loss weight λ via validation (e.g., λ ∈ {0.1, 0.5, 1.0}).

4.5 Evaluation Metrics

We evaluate all methods using standard metrics appropriate to each task:

- Legal (LEDGAR): accuracy and macro-F1 over clause types.
- Biomedical (PubMedQA): accuracy over answer labels.
- Programming (CodeSearchNet QA): mean reciprocal rank (MRR) and recall@K for retrieval; accuracy for binary relevance classification.
- Finance (FiQA Sentiment): accuracy and macro-F1 over sentiment labels.

We report results averaged over multiple random seeds and include standard deviations to assess stability. We focus primarily on the low-resource settings (e.g., 1k and 5k labeled examples), and also provide results for larger training sets where available to analyze the data efficiency of each method.
