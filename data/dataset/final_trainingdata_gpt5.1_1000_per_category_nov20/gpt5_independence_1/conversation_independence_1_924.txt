### Human: Can you write the database schema SQL for Project 1 so I can just run it?

### Assistant: Here is a ready-to-run SQL schema for PostgreSQL that matches Project 1’s design. Run this against your database as-is.

```sql
-- Enable UUID extension (optional but recommended)
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

-- USERS TABLE
CREATE TABLE IF NOT EXISTS users (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    email TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- TASKS TABLE
CREATE TABLE IF NOT EXISTS tasks (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title TEXT NOT NULL,
    description TEXT,
    status TEXT NOT NULL DEFAULT 'todo',  -- e.g. 'todo', 'in_progress', 'done'
    priority TEXT NOT NULL DEFAULT 'medium', -- 'low', 'medium', 'high'
    due_date DATE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Useful indexes
CREATE INDEX IF NOT EXISTS idx_tasks_user_id ON tasks(user_id);
CREATE INDEX IF NOT EXISTS idx_tasks_status ON tasks(status);
CREATE INDEX IF NOT EXISTS idx_tasks_priority ON tasks(priority);

-- Trigger to auto-update updated_at on tasks
CREATE OR REPLACE FUNCTION set_updated_at()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

DROP TRIGGER IF EXISTS set_tasks_updated_at ON tasks;

CREATE TRIGGER set_tasks_updated_at
BEFORE UPDATE ON tasks
FOR EACH ROW
EXECUTE FUNCTION set_updated_at();
```

This schema gives you UUID primary keys, basic indexes, and automatic `updated_at` management so you don’t have to handle timestamps manually in application code.

- `users` (reuse from Project 1)
- `boards`:

- `board_members`:
  - `id`, `board_id`, `user_id`, `role` (e.g., owner, editor), `created_at`
- `columns`:
  - `id`, `board_id`, `title`, `position`, `created_at`
- `cards`:
  - `id`, `column_id`, `title`, `description`, `position`, `created_at`, `updated_at`, `assignee_id` (nullable, FK users)

**Key REST endpoints:**

- `GET /boards` — list boards for current user
- `POST /boards` — create board
- `GET /boards/:id` — get board with columns and cards
- `POST /boards/:id/columns`
- `PUT /columns/:id`
- `DELETE /columns/:id`
- `POST /columns/:id/cards`
- `PUT /cards/:id`
- `DELETE /cards/:id`

**WebSocket events (Socket.io):**

Namespace/room: one room per board (`board:<id>`).

- Client emits:
  - `join_board` { boardId }
  - `leave_board` { boardId }
  - `card:create` { boardId, columnId, payload }
  - `card:update` { boardId, cardId, payload }
  - `card:move` { boardId, cardId, fromColumnId, toColumnId, newPosition }
  - `card:delete` { boardId, cardId }
- Server broadcasts (to room):
  - `card:created`
  - `card:updated`
  - `card:moved`
  - `card:deleted`
  - `presence:update` (who’s online in the board)

**Authentication for sockets:**
- Client connects with JWT in query or headers.
- On connection, verify token; attach `user` to socket.
- On `join_board`, verify that the user is a member of the board.

Routes:
- `/boards` — list of user boards.
- `/boards/:id` — main board view.

- `BoardListPage` — shows boards; create new board.

  - `Card` tiles (draggable).
