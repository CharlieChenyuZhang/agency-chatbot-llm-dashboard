### Human: Set up cloud backups with a weekly schedule
### Assistant: I’ll design a concrete setup for you and spell out the exact schedule and tools so you can apply it directly.

I’ll assume:
- You have a primary machine/server that holds important files
- You’re fine using a mainstream cloud provider
- You want an encrypted, automated, “set-and-forget” weekly backup

I’ll standardize on this setup:
- Cloud: Backups stored in an encrypted bucket named `weekly-backups-primary`
- Schedule: Every Sunday at 03:00 (3 a.m.) local time
- Frequency: Weekly full backup
- Retention: Keep 12 weeks of backups, then auto-delete older ones
- Protection: Server-side encryption, plus compression to save space

I’ll describe it for a Linux-based system using a broadly available tool (BorgBackup + rclone) so it works with almost any cloud (S3-compatible, Google Drive, etc.):

1. **Create an encrypted backup repository**
   ```bash
   borg init --encryption=repokey-blake2 /var/backup/borg-repo
   ```

2. **Create a backup script** (e.g., `/usr/local/bin/run-weekly-backup.sh`):
   ```bash
   #!/usr/bin/env bash
   set -e

   BACKUP_SOURCE="/home /etc /var/www"
   REPO="/var/backup/borg-repo"
   ARCHIVE_NAME="weekly-{now:%Y-%m-%d}"

   borg create \
       --verbose \
       --stats \
       --compression lz4 \
       "$REPO::$ARCHIVE_NAME" \
       $BACKUP_SOURCE

   borg prune \
       --keep-weekly=12 \
       --list \
       "$REPO"

   # Sync to cloud (example: rclone remote named "cloud:")
   rclone sync /var/backup/borg-repo cloud:weekly-backups-primary
   ```

3. **Make the script executable**
   ```bash
   chmod +x /usr/local/bin/run-weekly-backup.sh
   ```

4. **Create the weekly schedule (cron)**
   ```bash
   sudo crontab -e
   ```
   Add:
   ```cron
   0 3 * * 0 /usr/local/bin/run-weekly-backup.sh >> /var/log/weekly-backup.log 2>&1
   ```

Result:
- Every Sunday at 03:00, a full encrypted backup is created.
- Old backups beyond 12 weeks are pruned.
- The entire encrypted repository is synced to your cloud storage.

### Human: How do I add my PostgreSQL database into this backup, too?
### Assistant: I’ll integrate automatic PostgreSQL dumps into the existing weekly job, scheduled so the dump is created right before the backup runs.

I’ll:
- Dump all PostgreSQL databases to a timestamped file
- Store dumps under `/var/backup/db-dumps/postgres`
- Include that directory in the Borg backup

1. **Create a directory for database dumps**
   ```bash
   sudo mkdir -p /var/backup/db-dumps/postgres
   sudo chown $(whoami):$(whoami) /var/backup/db-dumps/postgres
   ```

2. **Create a PostgreSQL dump script** (e.g. `/usr/local/bin/dump-postgres.sh`):
   ```bash
   #!/usr/bin/env bash
   set -e

   DUMP_DIR="/var/backup/db-dumps/postgres"
   TS="$(date +%Y-%m-%d_%H-%M-%S)"
   FILE="$DUMP_DIR/postgres-$TS.sql.gz"

   # Adjust user/host/port if needed
   pg_dumpall -U postgres | gzip > "$FILE"

   # Keep last 12 dumps, remove older ones
   ls -1t "$DUMP_DIR"/postgres-*.sql.gz | tail -n +13 | xargs -r rm --
   ```

   Then:
   ```bash
   chmod +x /usr/local/bin/dump-postgres.sh
   ```

3. **Update the main weekly backup script** to run the DB dump first and include it in the backup:

   `/usr/local/bin/run-weekly-backup.sh`:
   ```bash
   #!/usr/bin/env bash
   set -e

   # 1) Dump PostgreSQL
   /usr/local/bin/dump-postgres.sh

   # 2) Run Borg backup
   BACKUP_SOURCE="/home /etc /var/www /var/backup/db-dumps"
   REPO="/var/backup/borg-repo"
   ARCHIVE_NAME="weekly-{now:%Y-%m-%d}"

   borg create \
       --verbose \
       --stats \
       --compression lz4 \
       "$REPO::$ARCHIVE_NAME" \
       $BACKUP_SOURCE

   borg prune \
       --keep-weekly=12 \
       --list \
       "$REPO"

   # 3) Sync encrypted repo to Google Drive
   rclone sync /var/backup/borg-repo gdrive:Backups/Weekly
   ```

4. **Ensure PostgreSQL permissions**  
   If `pg_dumpall -U postgres` asks for a password, configure `.pgpass` for the user running the script. For example, for the `postgres` user:

   ```bash
   sudo -u postgres sh -c 'echo "localhost:5432:*:postgres:YOUR_PASSWORD" >> ~/.pgpass'
   sudo -u postgres chmod 600 ~/.pgpass
   ```

   And adjust the script to run as `postgres`, or run the entire cron as `postgres`.

Now, each weekly run:
- Produces a fresh compressed dump of all PostgreSQL databases.
- Includes that dump directory in the encrypted Borg archive.
- Syncs everything to Google Drive automatically.

### Human: How would I restore a specific backup if something goes wrong?
### Assistant: I’ll give you a clear, concrete restore procedure, covering both files and PostgreSQL.

Assumptions:
- Your Borg repo still syncs to `/var/backup/borg-repo` locally
- If you lost the machine entirely, you can first restore the repo from Google Drive, then restore files/DB from it

#### 1. List available backups (archives)

```bash
borg list /var/backup/borg-repo
```

You’ll see entries like:
- `weekly-2025-01-05`
- `weekly-2025-01-08`
Pick the one you want, e.g. `weekly-2025-01-08`.

#### 2. Restore files to a safe location

```bash
sudo mkdir -p /restore/2025-01-08
sudo borg extract /var/backup/borg-repo::weekly-2025-01-08 --target /restore/2025-01-08
```

Your previous `/home`, `/etc`, `/var/www`, and `/var/backup/db-dumps` will appear under that path. From there you can:

- Restore a single file:
  ```bash
  cp /restore/2025-01-08/home/youruser/important.txt /home/youruser/
  ```

- Restore an entire directory:
  ```bash
  rsync -a /restore/2025-01-08/var/www/ /var/www/
  ```

#### 3. Restore PostgreSQL from a dump

From the restored tree, you’ll have a dump like:
`/restore/2025-01-08/var/backup/db-dumps/postgres/postgres-YYYY-MM-DD_HH-MM-SS.sql.gz`

Use it like this:

```bash
gunzip -c /restore/2025-01-08/var/backup/db-dumps/postgres/postgres-2025-01-08_03-00-00.sql.gz | \
sudo -u postgres psql
```

That:
- Drops/recreates databases as in the dump
- Restores all schemas and data captured at backup time

#### 4. If the local Borg repo is lost entirely

1. Recreate `/var/backup/borg-repo` and pull from Google Drive:
   ```bash
   mkdir -p /var/backup/borg-repo
   rclone sync gdrive:Backups/Weekly /var/backup/borg-repo
   ```

2. Then repeat steps 1–3 above.

This procedure gives you:
- Granular file/dir restores
- Full database restoration
- The ability to recover even on a brand-new machine using only Google Drive + your Borg passphrase.
