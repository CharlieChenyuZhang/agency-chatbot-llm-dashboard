#### 1. Notebook structure

Create these top-level sections (folders / notebooks / databases):

1. **Inbox**
2. **Today**
3. **Projects**
4. **Areas**
5. **Archive**
6. **Reference**

Inside each:

- **Inbox**
  - Raw, unprocessed notes
  - Every quick thought, link, snippet lands here first

- **Today**
  - One daily note per day: `YYYY-MM-DD – Daily`
  - Used to plan, log, and think during the day

- **Projects**
  - One note per active project
  - Naming: `PRJ – [Outcome]`  
    Example: `PRJ – Launch new landing page`

- **Areas**
  - Ongoing responsibilities (no clear end date)
  - Examples: `Fitness`, `Career`, `Finances`, `Family`, `Learning`

- **Reference**
  - Stable information you want to keep
  - Examples: `Books`, `Recipes`, `How-tos`, `Meeting templates`

- **Archive**
  - Completed projects
  - Obsolete notes / old versions

---

#### 2. Capture rules

Whenever something comes in (thought, task, idea, quote, link), follow these **non-negotiable rules**:

**Rule 1 – Capture fast, clarify later**
- Never “organize” when capturing.
- Everything goes to **Inbox** immediately.
- Capture in the shortest possible form that is still understandable.

**Rule 2 – Always add a type tag**
When you capture, prepend a short code at the start of the note or line:

- `T:` = Task (action needed)  
  Example: `T: Email Maria about Q4 budget`
- `I:` = Idea  
  Example: `I: Workshop on "Deep work for teams"`
- `R:` = Reference info  
  Example: `R: Command to restart server: systemctl restart nginx`
- `M:` = Meeting / conversation note  
  Example: `M: 1:1 with Alex – Feb`
- `L:` = Link / resource  
  Example: `L: Article on note-taking systems – [URL]`
- `J:` = Journal / reflection  
  Example: `J: Feeling overwhelmed, pattern seems to be…`

**Rule 3 – One thought per line**
- Don’t bury multiple ideas in one long paragraph in the Inbox.
- Each new thought → new line (or new bullet).

**Rule 4 – Capture context in 10 seconds or less**
When capturing, add a one-line “why” if it’s not obvious:

- Format: `Why: …`
- Example:  
  `I: Try weekly demo sessions`  
  `Why: Could reduce misunderstandings with stakeholders`

---

#### 3. Daily workflow

Every day, follow this **fixed routine**:

**Morning (5–10 minutes)**  
1. Create a daily note in **Today**: `YYYY-MM-DD – Daily`
2. Add three sections (fixed template):

   - `# Top 3`  
     - [ ] Task 1  
     - [ ] Task 2  
     - [ ] Task 3  

   - `# Schedule`  
     Rough outline of meetings / blocks.

   - `# Notes`  
     Free-form notes for the day.

3. Move any unfinished **Top 3** from yesterday into today (or deliberately drop them).

**During the day**
- All quick notes still go into **Inbox** (not Today).
- Use Today only for:
  - Today’s plan
  - Brief log of what happened
  - Pointers to other notes

**End of day (10–15 minutes) – Inbox Triage**
Process **Inbox** completely using this fixed decision tree:

For each item in Inbox:

1. **Is it a task? (`T:`)**  
   - If it takes **< 2 minutes** → do it now.  
   - If it takes longer:
     - Link it to the proper **Project** or **Area** note.
     - Optionally mark priority: `(H)`, `(M)`, `(L)`.
     - Remove it from Inbox.

2. **Is it an idea / journal / meeting / reference? (`I:`, `J:`, `M:`, `R:`, `L:`)**
   - Does it belong to an existing **Project**?  
     → Append or link it there.
   - Does it belong to a long-term **Area**?  
     → Store it in that Area note.
   - If it’s pure reference:
     → Move to a suitable **Reference** note (or create one).
   - If it’s not worth keeping:
     → Delete.

End goal: **Inbox empty every day**.

---

#### 4. Weekly review

Once a week (e.g., Sunday, 20–30 minutes):

1. **Projects**
   - Scan all `PRJ – …` notes.
   - For each: write a 1–2 line status.
   - Add / update next 1–3 concrete actions.

2. **Areas**
   - Pick 2–3 Areas each week (rotate).
   - Ask: “What’s one small improvement I can make here this week?”
   - Add actions as tasks under the relevant Project or Area.

3. **Reference**
   - Quickly scan for clutter or duplicates.
   - Merge or delete as needed.

4. **Archive**
   - Move finished Projects from **Projects → Archive**.
   - Add a short “Lessons learned” line at the top of each archived project.

You now have a complete system: structure, capture rules, daily flow, and review cycle. You can implement this as-is in your current app.

#### 4. Processing Inbox in Obsidian

Every evening:

1. Open `00_Inbox`.
2. If you have many small timestamped notes:

     - Move content to the right Project / Area / Reference / Today note.
     - Delete the now-empty Inbox note.
3. If you use a single rolling Inbox note:
   - Split it as you process:
     - Select lines that belong to a Project → use “Move selection to new file” (or cut-paste) into the relevant note.

Conventions while processing:

- Tasks:
  - Convert to checkboxes with context:  
    `- [ ] Email Sarah about contract ([[PRJ – New client onboarding]])`
- Ideas:
  - Store under the relevant Project or Area’s **Notes** section.
- Reference:
  - Create topic-specific notes in `04_Reference` (e.g., `R – Linux server commands`).
- Meetings:
  - Dedicated notes in `04_Reference/Meetings` with title:  
    `MTG – [Person/Team] – YYYY-MM-DD`.

  - From Projects to specific Reference notes.

This turns the vault into a navigable graph where:
- Daily notes = timeline.
- Projects = work units.
- Areas = long-term categories.

#### 1. Relaxed review frequency

Instead of “Inbox empty every day”, adopt:

- **Hard rule:** Inbox must be cleared **at least 3 times per week** (e.g., Mon, Wed, Sat).
- On other days, you’re allowed to:
  - Only use the daily note.
  - Capture into Inbox without processing it.

---

#### 2. Adjusted workflow

**Every day (minimum viable):**

1. Open today’s note in `01_Today`.
2. Set **Top 1** instead of Top 3 (make it easier to succeed):

```markdown
## Top 1
- [ ] Most important thing today
```

3. Capture during the day as usual (Inbox or daily note).

**Processing days (3x/week, 15–20 min):**

On Mon / Wed / Sat:

1. Process **Inbox** completely as before.
2. While processing, if too much has accumulated:
   - First, delete obvious junk.
   - Then, only fully file:
     - Tasks due this week.
     - Items directly tied to active Projects or Areas.
   - Move everything else into a parking note:  
     `R – Someday/maybe` and skim it only during weekly review.

---

#### 3. Safety nets

To prevent things slipping:

- **Deadlines:**  
  - Whenever you capture a task with a real date, add it directly to today’s note or the specific day where it must show up:  
    `- [ ] Pay rent (due 2025-12-01)` inside the relevant daily note or a `Calendar` / `Tasks` plugin query.

- **Weekly review becomes non-negotiable**  
  - Even if you miss a midweek review, do **not** skip the weekly one.
  - During weekly review, you:
    - Clear Inbox.
    - Check the last 7 days of daily notes for any unchecked tasks.
    - Update Projects and Areas.

This way, the system still works if:
- Some days you only jot things down.
- Organization happens in larger, less frequent batches.
