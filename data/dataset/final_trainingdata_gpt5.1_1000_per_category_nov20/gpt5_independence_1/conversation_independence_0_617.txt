### Human: Explain the general strategy first.
### Assistant: A general strategy for a minimal reproducible case is:

1) Start from a known failing scenario (full stack).  
2) Remove components one by one (UI layer, other services, background jobs) while checking if it still fails.  
3) Simplify the input (smaller payload, fewer steps, minimal data) each time, verifying the bug still appears.  
4) Replace external dependencies with mocks/fakes where possible.  
5) Stop when you have the smallest, fastest scenario that still reproduces the issue.

### Assistant: Here’s a high-level decision tree you can use:

   - If yes → Go to 2.

2) Can I bypass the UI and call the API/service directly with the same effect?

### Human: Focus on the binary search idea.
### Assistant: The “binary search” idea in debugging complex systems is:

1) Identify the start and end of the problematic flow (e.g., UI button → DB write).  
2) Choose a middle point (e.g., API boundary or message queue) and check if the state is already wrong there.  
3) If the state is wrong at the middle point, the bug is “earlier”; if it’s correct, the bug is “later.”  
4) Repeat, each time picking a middle point in the remaining suspect range, until only one component or boundary remains.
