### Human: What’s the difference between `if` and `elif` exactly?
### Assistant: Each `if` or `elif` is a condition the program checks in order, top to bottom: - `if` is always checked. - `elif` (“else if”) is only checked if all previous conditions (`if` and earlier `elif`s) were false. - Once one condition is true, Python runs that block and skips the rest. For example: ```python x = 85 if x >= 90: print("A") elif x >= 80: print("B") elif x >= 70: print("C") else: print("D or F") ``` Here: - It checks `x >= 90` → false. - Then checks `x >= 80` → true, so it prints `"B"` and stops checking. If you used multiple `if` statements instead: ```python if x >= 90: print("A") if x >= 80: print("B") ``` With `x = 95`, you’d get both `"A"` and `"B"`, which usually isn’t what you want. ### Human: Why do we use `while True` instead of something like `while guess != secret`?
### Assistant: Using `while True` creates an infinite loop that you control from inside with `break`. This pattern is handy when: 1) You don’t have an initial value for `guess` yet. 2) You want all the exit logic to live in one clear place (inside the loop body). If you wrote: ```python guess = -1 while guess != secret: guess = int(input("Guess: ")) # ... ``` You’d need to give `guess` some dummy initial value (`-1` here) only to make the loop condition valid. With `while True`, you skip that hack: ```python while True: guess = int(input("Guess: ")) if guess == secret: print("Correct!") break ``` You’ll encounter this pattern a lot when reading real code, so it’s useful to get comfortable with it now. ### Human: I guess `return` gives a value back that I can store, while `print` just shows it on the screen?
### Assistant: Exactly. More precisely: - `print(...)` sends text to the screen and returns `None`. It’s for humans. - `return ...` sends a value back to the caller so the program can keep using it. It’s for your code. For example: ```python def square(x): return x * x n = square(4) # n becomes 16 print(n) # now we display 16 ``` If you replaced `return x * x` with `print(x * x)`, then: - The function would display 16. - But it would *return* `None`, so `n` would be `None`, which is not useful for further calculations.
