### Human: Set up a note-taking system with capture rules
### Assistant: I’ll set up a complete, opinionated system you can drop into any app (Obsidian, Notion, Apple Notes, Evernote, etc.). I’ll assume a general-purpose notes app with folders/tags and search. I’ll define: 1) Structure (folders/tags) 2) Note types 3) Capture rules (when, where, how) 4) Daily workflow --- 1) Structure Create 5 top-level areas: - Inbox - Tasks - Projects - Reference - Archive If your app doesn’t support folders, use tags like `#inbox`, `#task`, etc. Inbox - One single place where everything new lands first. - No subfolders. Just a stream of raw, unprocessed notes. Tasks - Where individual action items live (things you must do). - Each task is either: - a line in a running task list, or - its own “Task” note (if complex). Projects - One note per active project (anything with multiple steps and a clear outcome). - Example: “Project – Launch new website”. Reference - Long-term information you want to keep: book notes, how-tos, meeting notes, etc. - Optional subfolders: `People`, `Work`, `Learning`, `Personal`. Archive - Completed projects, old notes you don’t need often but don’t want to delete. --- 2) Note types Define a few standard note types with clear roles: - Inbox note: anything you just captured, unprocessed. - Task note / task line: “Do X by Y because Z.” - Project note: describes goal, status, tasks, and key info. - Reference note: stable info (summaries, manuals, decisions). - Daily note: log for the day, quick capture and planning. --- 3) Capture rules Use these rules to decide what to do when something enters your head. Rule 1 – Single capture bucket per context - On computer: always capture into “Inbox” in your main notes app. - On phone: use a single “Quick Capture” note or folder named “Inbox – Mobile”. - On paper: use one notebook page per day as your capture page. Rule 2 – Capture if it takes > 10 seconds to remember If a thought, idea, or to-do would take more than 10 seconds to mentally reconstruct later, capture it now. Rule 3 – Use atomic notes One note = one main idea, when possible. Examples: - Instead of “Random work stuff”, create “Meeting – Q2 planning – 2025-03-18”. - Instead of “Marketing ideas”, create “Idea – Product-led onboarding experiments”. Rule 4 – Mandatory metadata When capturing, always add at least: - Date - Context (meeting, book, idea, task, etc.) - Minimal title that would make sense to “future you”. Example titles: - “Task – Email Sarah about budget – due Fri” - “Idea – Newsletter topic: how to say no” - “Meeting – Team sync – 2025-03-18” Rule 5 – Tag at capture time (but lightly) Use at most 1–2 tags when you capture. Examples: - `#task`, `#idea`, `#meeting`, `#reading`, `#personal`, `#work` Do not overthink tags; they’re for filtering, not for perfect taxonomy. Rule 6 – Daily processing window Once per day (e.g., afternoon), process your Inbox until it’s empty: For each Inbox item: - Is it actionable (requires you to do something)? - Yes → Make it a Task or add it to a Project. - No → Reference or Delete. - Will you need it again? - Yes → Move to appropriate Project or Reference. - No → Delete or Archive. Rule 7 – Two-minute rule for tasks While processing: - If a task takes less than 2 minutes → do it immediately. - If more → move it to your Task list / app and link it to a Project if relevant. Rule 8 – Avoid mixed notes Don’t mix: - Tasks and long reference text in the same note. - Multiple meetings in one note. If they’re mixed in the Inbox, split them during processing. --- 4) Daily workflow Morning (5–10 minutes) 1) Open today’s Daily note: - Title: `Daily – 2025-11-21` 2) Write: - Top 3 priorities - Any key meetings with times 3) Pull key tasks from Tasks/Projects into today’s Daily note as “focus tasks”. During the day - Capture into Inbox or into today’s Daily note (which you then move to Inbox at end of day if needed). - For each meeting: - Create a new note: `Meeting – [Name] – YYYY-MM-DD`. - Capture decisions and action items. - Mark action items with a clear prefix like `ACTION:` so they’re easy to find and convert to tasks later. Afternoon / End of day (10–15 minutes) Process Inbox completely: - Convert action items to Tasks. - Link tasks to relevant Project notes. - Move stable notes to Reference or the appropriate Project. - Empty Inbox (everything moved, deleted, or turned into tasks). Weekly (20–30 minutes) - Review Projects: mark some as completed, move to Archive. - Clean Tasks: remove or defer irrelevant ones. - Scan Reference for any notes that should be turned into Projects (e.g., “idea that turned into a real thing”). This gives you: - One place to capture - Clear rules for where things go - A daily and weekly loop to keep it clean and usable

### Human: What exact capture rules should I follow during a busy workday?
### Assistant: Use a few simple, strict rules so you don’t think about the system at all while you’re busy. Rule A – One decision only: “Capture or ignore?” During work, never decide where something belongs. Only decide: - Capture it now, or - Let it go. If you capture → it goes to `00 Inbox`. No exceptions. Rule B – Capture formats Use short, structured prefixes so processing is easy later: - `t/` for tasks - Example: `t/ Send updated deck to Maria by Thu` - `m/` for meeting notes (if you can’t open a fresh meeting note yet) - Example: `m/ 1:1 with John – discussed promotion timeline` - `i/` for ideas - Example: `i/ Idea: monthly internal newsletter with customer stories` - `r/` for reading or links - Example: `r/ Article – “Continuous discovery habits” – revisit this weekend` Everything else can be free-form text; the prefix is mainly for tasks and ideas. Rule C – Time-based rule - If capturing will take less than 30 seconds → capture. - If it would take longer (long thought, long email draft) → create a task instead: - `t/ Flesh out idea about X (15 mins deep work block)` Rule D – Context-based rule When something appears: - In a meeting: - Write only decisions and action items. - Mark all action items with a clear prefix: - `ACTION: Follow up with finance about budget` - In email/Slack: - If reply < 2 minutes → reply now. - If > 2 minutes → capture as task: - `t/ Write detailed reply to [Name] about [Topic]` Rule E – Don’t organize mid-stream If you’re in the middle of focused work: - Do not open other folders. - Drop a minimal note into Inbox and return immediately to what you were doing. Example: - You’re coding and remember: “renew license” - Capture: `t/ Renew software license (check accounting for invoice)` in Inbox and go back. Rule F – End-of-block mini-processing (optional) After each major block of work (e.g., 90 minutes, or after a meeting block): - Spend 3–5 minutes: - Skim `00 Inbox` - Convert the most urgent items to Tasks - Leave less urgent items for your main daily processing Rule G – Hard limit on raw stuff If `00 Inbox` has more than, say, 30 items, you must process before adding more: - This prevents the system from becoming a junk drawer. These rules keep your thinking simple during the day: - While busy: “Does this matter?” → if yes, quick capture to Inbox with a tiny prefix. - At processing time: you sort and promote things properly.
### Human: How should I handle meeting notes with this system, step by step?
### Assistant: I’ll define a precise meeting-notes workflow, assuming Apple Notes but applicable anywhere. Before the meeting 1) Create a new note in `03 Reference` (or `02 Projects` if it’s tied to a specific project). 2) Title it: - `Meeting – [Person/Team] – [Topic] – YYYY-MM-DD` - Example: `Meeting – Marketing team – Q2 campaigns – 2025-03-20` 3) At the top, paste a simple template: - **Attendees:** - **Purpose:** - **Agenda:** - **Notes:** - **Decisions:** - **Actions:** During the meeting 4) Capture very lightly under **Notes**: - Bullet points only - No full sentences unless necessary 5) When something is decided: - Write under **Decisions:** as you go. - Format: short bullet, one line per decision. 6) When an action item appears: - Immediately add under **Actions:** - Format: - `ACTION: [Owner] – [What] – [When]` - Example: `ACTION: You – Send updated roadmap to team by Mon` - Example: `ACTION: Maria – Draft Q2 campaign brief by Apr 5` Right after the meeting (5 minutes) 7) Scan the **Actions** section: - For your own actions: - Copy each line into your `Tasks – Work` note as checklist items. - Optionally prepend project tag or shorthand: `[Project: Q2 campaigns]`. - Optionally bold your name or you can remove other people’s actions if you don’t need to track them. 8) At the top of the meeting note, add a brief summary: - 2–3 bullet points under a header **Summary**: - “Agreed on 3 main Q2 campaigns” - “Timeline confirmed: April–June” - “Budget still pending approval” Filing and linking 9) If the meeting belongs to a project: - In the Project note (e.g., `Project – Q2 campaigns`), add a section: - **Meetings:** with a link back to this meeting note. 10) Leave the meeting note in `03 Reference` or move it into a subfolder `03A Work > Meetings` if you keep one. Review 11) During weekly review: - Quickly scan recent important meeting notes (e.g., last week). - Check that all meaningful `ACTION:` items have corresponding tasks. - If you see new work that’s actually a project, create a new Project note and link. This way: - Meeting notes live in Reference - Action items live in Tasks - Projects link everything together
