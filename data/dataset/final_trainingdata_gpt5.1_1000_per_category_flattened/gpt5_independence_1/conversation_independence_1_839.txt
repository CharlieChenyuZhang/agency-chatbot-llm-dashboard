### Human: I’d rather host it on my own domain than the GitHub URL. How are you handling that?
### Assistant: I’ll attach a custom domain to the same GitHub Pages–hosted blog so you keep free hosting but use your own URL. **1. Configure GitHub Pages for a custom domain** In your GitHub repo: - Go to **Settings → Pages** - Under **Custom domain**, enter `www.yourdomain.com` - Enable **“Enforce HTTPS”** GitHub automatically creates a `CNAME` file in the repo root with: ```text www.yourdomain.com ``` If it doesn’t exist, add it manually and commit. **3. Set DNS at your domain registrar** At your domain registrar (Namecheap, GoDaddy, Cloudflare, etc.), set: - For `www.yourdomain.com`: - Type: `CNAME` - Name/Host: `www` - Value/Target: `YOUR-GITHUB-USERNAME.github.io` - TTL: automatic / 30 min - For `yourdomain.com` (the bare root): - Either: - Add `A` records pointing to GitHub Pages IPs: - `185.199.108.153` - `185.199.109.153` - `185.199.110.153` - `185.199.111.153` - Or with a DNS provider that supports it, a `CNAME`-style redirect (often called “ALIAS/ANAME/flattening”) to `YOUR-GITHUB-USERNAME.github.io` or to `www.yourdomain.com`. Then set up a redirect from `yourdomain.com` → `https://www.yourdomain.com`. Many registrars have a simple “URL redirect” option for this. Once DNS propagates (up to a few hours), your blog will be available at `https://www.yourdomain.com` with GA tracking that domain directly. You don’t need to change any deployment steps; they keep working as-is.
