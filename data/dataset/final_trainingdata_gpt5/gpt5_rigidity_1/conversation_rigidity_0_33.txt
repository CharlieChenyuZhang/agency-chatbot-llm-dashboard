### Human: Okay. What exact fields should the Tasks database have?
### Assistant: Keep it lean:
- Name (title)
- Due date (date)
- Status (select: Next, Waiting, Scheduled, Someday)
- Priority (select: P1, P2, P3)
- Project (relation → Projects)
- Note (relation → Notes)
- Estimate (number, minutes)
- Context (multi-select: Home, Office, Errand, Deep, Quick)

That’s enough. Skip checkboxes and complex formulas—Notion formulas get brittle. If you need recurring or natural language dates, this is where Todoist is simply better.

### Human: How do I link tasks to notes in Notion?
### Assistant: Use relations both ways.
- In Tasks, add “Note” relation → Notes. Create a “New note” template that pre-fills the Task link.
- In Notes, add “Related tasks” relation → Tasks and turn on “Show on this page.”
- In Projects, add “Notes” relation → Notes and “Tasks” relation → Tasks.

In practice, you’ll open a task, click the Note relation, create a meeting note, and it auto-links. It works, but in Obsidian you can just use a [[note]] link or a unique ID and it’s instant.

### Human: What automations can I use inside Notion to keep tasks current?
### Assistant: Notion’s built-in automation is rudimentary. You can:
- Create a Button to set Status to Next and set Due date = today.
- Use a formula to flag “Due soon” (dateBetween(now(), prop("Due date"), "days") <= 2).
- Notion Calendar integration for date scheduling.
- Zapier/Make: capture from email or Slack into Tasks, but it’s slower than Todoist’s quick-add.

For recurring items, Notion is weak. Todoist wins with true recurring rules like “every 3rd business day.”

### Human: How should I handle “Waiting” tasks in Notion?
### Assistant: Minimal friction:
