### Human: Make me flashcards for key patterns.
### Assistant: Here are concise flashcards you can review before sessions:

- Sliding Window
  - Use when tracking counts/uniqueness in substrings/subarrays.
  - Template: expand right; while invalid, shrink left; track best.

- Two Pointers
  - Use on sorted arrays/strings to find pairs/triplets/partitions.
  - Move pointers based on comparison to target.

- Binary Search on Answer
  - Use when answer is monotonic wrt a predicate.
  - Template: while lo < hi: mid; if feasible(mid): hi=mid else lo=mid+1.

- Prefix Sum + Hash Map
  - Use for subarray sums, count of target-difference pairs.
  - Store earliest index for each prefix sum.

- Monotonic Stack/Queue
  - Use for next greater element, histogram, sliding window max.
  - Maintain increasing/decreasing structure.

- BFS/DFS
  - BFS: shortest steps/layers in unweighted graphs.
  - DFS: explore components, detect cycles, backtracking.

- Topological Sort
  - Use for ordering tasks with prerequisites.
  - Kahn’s algorithm (in-degrees) or DFS postorder.

- Union-Find (DSU)
  - Use to track connectivity/components efficiently.
  - Union by rank + path compression.

- Heap/Priority Queue
  - Use for k-th, merging, scheduling.
  - Min-heap for smallest-first; keep size k for top-k.

- Greedy + Intervals
  - Sort by end/start then pick earliest-compatible.
  - Exchange arguments: local optimal→global optimal.

- Dynamic Programming
  - Identify state, transition, base; iterate with correct order.
  - Optimize with rolling arrays or monotonic tricks.

- Backtracking
  - Build candidates; prune on invalid partials.
  - Common in subsets/permutations/combination sum.

### Assistant: That’s the ideal approach.
- Initialize map with {0: -1} to handle prefixes starting at index 0.
- Iterate i, keep running sum s.
  - If s not in map, store i.
  - If (s - k) in map, candidate length = i - map[s - k]; update best.
- Time O(n), space O(n).

Edge cases:
- All negatives or positives both fine.
- If k=0, ensures longest zero-sum subarray via same logic.

### Human: Let’s cover DP next. I struggle with it.
### Assistant: A simple framework:
1) Define state: what minimal info describes a subproblem?
2) Define transition: how to build from smaller states?
3) Base cases: trivial answers.
4) Order: ensure prerequisites computed first.
5) Result: where is the answer stored?

Example: Coin Change (min coins to make amount)
- State: dp[a] = min coins to make sum a.
- Init: dp[0] = 0; others = +inf.
- Transition: for coin c, dp[a] = min(dp[a], dp[a - c] + 1) for a >= c.
- Order: increasing a.
- Answer: dp[amount] if finite else -1.
- Pitfalls: use a large sentinel; iterate coins outer or inner consistently; watch unreachable states.
