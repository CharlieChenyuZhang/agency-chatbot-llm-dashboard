### Human: Can you draft one sample public article?
### Assistant: Sample public article (How-to)

Title: Connect Jira to AcmeApp
Summary: Link Jira projects to AcmeApp so teams can create and track issues directly from AcmeApp.

Prerequisites
- AcmeApp Admin role
- Jira Cloud admin access
- A test project in Jira

Steps
1) In AcmeApp, go to Settings → Integrations → Jira.
2) Select Connect Jira and sign in with your Jira admin account.
3) Choose the Jira site and grant requested permissions.
4) Map projects: Pick one or more Jira projects to link.
5) Set field mapping: Issue type, priority, labels.
6) Save and test: Create a test issue from AcmeApp and verify it appears in Jira.

Validation
- The test issue appears in the selected Jira project within 30 seconds.
- Updating the issue status in Jira reflects inside AcmeApp within 2 minutes.

Common errors
- 403 during connect: Your Jira account lacks admin rights. Ask a Jira org admin to complete the connection.
- Issues not syncing: Check project mapping and confirm the integration user has browse/create permissions.

Related
- Set up Slack notifications
- Create custom workflows in AcmeApp

### Human: How do we handle multilingual later without rebuilding?
### Assistant: With GitBook you can:
- Duplicate the main space per language (e.g., EN, ES, DE). Keep identical structure to simplify maintenance.
- Add a language switcher to your homepage and cross-link between languages.
- Use a translation workflow: export articles for translators or connect a localization tool that supports GitBook exports; maintain a glossary and style guide.
- Track “source of truth” in EN and set a “needs retranslation” tag that triggers when EN changes.

If you anticipate heavy localization (5+ languages, frequent releases), a static-site approach like Docusaurus + an i18n workflow and a translation platform can scale better, but it’s more engineering-heavy. For now, GitBook’s approach should be sufficient.
