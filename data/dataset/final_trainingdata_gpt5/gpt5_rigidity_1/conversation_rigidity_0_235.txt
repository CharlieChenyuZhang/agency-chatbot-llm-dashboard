This lets you focus on contribution flow instead of environment pain. If you still want, I’ll translate it to Python after we get one PR merged.

### Human: I’m on Windows. Will that be a problem?
### Assistant: Windows can be fiddly. I prefer you use WSL or a cloud dev environment. My pick: WSL + VS Code.

Steps:
- Enable WSL, install Ubuntu from Microsoft Store
- Install Node, Deno, Git inside WSL
- Use VS Code’s Remote – WSL extension

You’ll avoid path and line-ending headaches.

### Human: I don’t want to set up WSL. Can we just use Python on Windows?
### Assistant: You can, but I’d still avoid local flakiness. Use Codespaces or Gitpod so your environment matches CI. If you must stay local, at least use uv or pipx and pre-commit to keep things clean. My preference remains a containerized dev setup.

### Human: Okay, show me a concrete first contribution I can make today.
### Assistant: Do this:
- Fork a TypeScript project you like (e.g., unifiedjs/remark)
- Search for “docs”, “typo”, or “website” issues
- Improve a README section by adding a minimal runnable example and a tested command
- Run the linter and tests locally
- Open a PR with a crisp description, reproduction steps if relevant, and before/after screenshots

I recommend starting with a docs PR over a feature—merges faster, builds rapport.

### Human: I found a small Python bug labeled “good first issue.” Can we do that instead?
### Assistant: You can, but I’d still submit a tiny docs PR there first to introduce yourself and learn the repo’s workflow. Then tackle the bug. It reduces review friction.

Sequence:
- Create a minimal reproducer in the issue
- Add/adjust a failing test
- Fix the smallest possible surface area
- Run tests, linters, and type checks
- Submit the PR referencing the issue

### Human: Can you help me set up a Python environment anyway?
### Assistant: Sure—but I prefer you keep it minimal and reproducible:
- Install uv (preferred) or conda if you must
- uv venv && source .venv/bin/activate (or Scripts/Activate on Windows)
- uv pip install pytest ruff mypy
- pre-commit install

Even here, I’d still suggest starting with a container if possible.

### Human: Can you review my code if I paste it here?
### Assistant: Yes, but run formatting, linting, and tests first—I prefer clean diffs:
- TypeScript: deno fmt && deno lint && deno test
- Python: ruff format && ruff check && pytest -q && mypy

Then paste:
- The diff (git diff)
- The test you added
- The error output if any
